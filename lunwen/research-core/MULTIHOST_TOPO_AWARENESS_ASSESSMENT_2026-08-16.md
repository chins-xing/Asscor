# 多主机并发评估 — 网络拓扑感知能力与初级主机分类评估

**日期**: 2026-08-16 | **版本**: v0.2.3 | **环境**: Containerlab 14 节点中形网络（WSL2 / Intel 146KF / 32G）

## 一、测试环境

```
s5720 真实网络 (192.168.1.0/24) ── 82580 物理网卡 ── r1 (MASQUERADE NAT 出口)
        │
     edge0 (ASSCOR-kernel :50051, mTLS, v0.2.3)
        │ 10.10.0.0/24
     r1 (FRR/OSPF 骨干) ──┬── r2 ── host1 (10.10.1.10) / host2 (10.10.2.10)
                          ├── r3 ── host3 (10.10.3.10) / host4 (10.10.4.10)
                          ├── r4 ── host5 (10.10.5.10) / host6 (10.10.6.10)
                          └── r5 ── host7 (10.10.7.10) / host8 (10.10.8.10)
```

- 8 台主机分属 8 个独立 /24 子网（经 OSPF 多跳互联），各跑一个 ASSCOR-agent
- 每台主机独立 mTLS 证书（host1-8 ↔ 8 条身份绑定持久化）
- 全部容器为 ubuntu:24.04 精简镜像（同质基线）

## 二、多主机并发评估结果

| 指标 | 结果 |
|------|------|
| 并发注册 | 8/8 accepted（独立证书，身份绑定 8 条持久化） |
| 并发评估 | 8 台全部完成，每台 80 检查项（51 失败），无串扰 |
| 同质基线分数 | **8 台 SSAM 总分完全相同：58.27**（AS=58, BC=60, OT=0, RS=0, KS=24） |
| PRISM 状态 | 全部 Untrusted / collapsing（collapse_risk 0.9076） |

**结论**：多主机并发评估功能正常，但**同质主机产生同质分数**——评估结果的区分度完全来自主机自身差异。

## 三、网络拓扑感知能力评估

### 3.1 采集链路（已确认工作）

```
agent collectNetworkInfo() ──→ Heartbeat.NetworkInfo ──→ kernel:
   LocalIPs/Subnets/NetworkZone      │
                                     ├─→ SPC LocalAsset.NetworkZone（态势区域）
                                     └─→ topology.RecordTopology(hostID, subnets)
                                          └─→ SRD 传播边（subnet 重叠 → 风险扩散）
                                          └─→ Locator（攻击者子网定位 + 横向移动范围）
```

- 8 台全部上报：`zone=internal, ips=2, subnets=2`（eth0 mgmt + eth1 拓扑网段）
- PRISM 评估中可见 `propagation_edges`（真实拓扑传播边，risk_transmission=0.3）

### 3.2 ✅ 实证：拓扑位置影响风险动力学分数

| 主机 | 首轮扩散边 | 首轮 PRISM 分数 | 次轮扩散边 | 次轮 PRISM 分数 |
|------|:---:|:---:|:---:|:---:|
| host1 | 0 | **58.27** | 7 | **43.7** |
| host2 | 1 | 50.98 | 7 | 43.7 |
| host3 | 2 | 47.95 | 7 | 43.7 |
| host4 | 3 | 45.63 | 7 | 43.7 |
| host5-8 | 4-7 | 43.7 | 7 | 43.7 |

SSAM 分数不变（58.27），PRISM 分数随接收的传播边数量递减至 prop_cap 封顶——**拓扑扩散真实作用于风险动力学**。

### 3.3 ⚠️ 发现的缺陷

1. **管理网段污染（P1）**：agent 上报的 Subnets 包含 containerlab 管理网 `172.20.20.0/24`（所有节点共享）→ 拓扑判定 8 台主机"同子网全互达"→ 每台 7 条扩散边。真实拓扑中 8 台主机分属 8 个不同 /24（仅经路由器互联），不应视为直连可达。**修复方向**：agent 过滤虚拟/管理网段（或 kernel 侧按网段白名单过滤），仅上报业务网段。
2. **评估时序依赖（P1）**：同质主机的 PRISM 分数依赖评估时刻的拓扑信息完整度（host1 首轮 58.27 vs 次轮 43.7）。同一主机不同时间评估分数不同，且与自身安全状态无关。**修复方向**：拓扑快照应在评估开始时统一（或传播边按"已注册主机全集"计算，而非按上报顺序累积）。
3. **NetworkZone 粒度粗（P2）**：`inferZone` 仅按私有/公网启发式（internal/public/dmz），8 台全部 internal。私有网段内部不做区域细分（无 web/db/app 等角色区域）。
4. **采集不完整（P2）**：`NetworkInfo.Gateways/Neighbors` 字段已定义但 agent **未采集**（代码只填 LocalIPs/Subnets/NetworkZone）——默认网关与 ARP 邻居信息缺失，Locator 的"横向移动范围"实际退化为纯 subnet 重叠判断。

## 四、初级主机分类能力评估

### 4.1 现状

- **无内置分类字段**：评估结果（AssessmentResult）无 role/class/group 字段；kernel 无主机分组机制。
- **可用的分类数据基础**：final_score / 五域分 / PRISM 语义状态与趋势 / 检查项 passed+detail / 子网 / NetworkZone / 身份绑定。

### 4.2 ✅ 实证：差异化主机可被评估区分

制造差异后（host1 良好 sshd_config、host2 差配置、host3-8 无配置）：

| 主机 | 总分 | AS 域 | AS-003 | 检查 detail（分类语义） |
|------|:---:|:---:|:---:|------|
| host1 | **59.09** | **68** | ✅ | SSH强认证策略已正确配置 |
| host2 | 58.27 | 58 | ❌ | 允许空密码登录; 允许root远程密码登录; 未禁用密码认证 |
| host3-8 | 58.27 | 58 | ❌ | 无法读取 SSH 配置: no such file |

- **数值区分**：host1（合规）总分 59.09 > 其余 58.27
- **语义区分**：host2（配置存在但不合规）与 host3-8（配置缺失）分数相同但 **detail 语义可区分**——检查项 detail 可作为细粒度分类特征

### 4.3 初级分类建议（基于现有数据可导出）

| 分类维度 | 依据 | 当前表现 |
|------|------|------|
| 拓扑分组 | subnets / 子网归属 | ✅ 8 台可分 4 组（r2/r3/r4/r5 下） |
| 风险分级 | final_score / PRISM 状态 | ⚠️ 同质时无区分，需差异化 |
| 合规语义 | 检查项 passed + detail | ✅ 可区分"配置缺失/不合规/合规" |
| 网络区域 | NetworkZone | ⚠️ 当前全 internal，粒度粗 |

## 五、结论

1. **多主机并发评估**：功能完整可用（8 台并发、身份隔离、无串扰）。
2. **拓扑感知**：链路已打通且真实影响 PRISM 风险扩散——这是 ASSCOR 的差异化能力；但存在管理网段污染与评估时序依赖两个 P1 缺陷，需修复后才算"可靠感知"。
3. **初级主机分类**：ASSCOR **无内置分类**，但数据基础完整，可按子网/分数/检查语义导出初级分类；同质环境无法自动区分主机，需结合主机差异化（服务/配置/user_check）与拓扑属性。

## 六、修复优先级建议

| 级别 | 项 | 方向 |
|:---:|------|------|
| P1 | 管理网段污染扩散边 | agent 过滤管理/虚拟网段 或 kernel 网段白名单 |
| P1 | 评估时序导致 PRISM 分数漂移 | 评估时统一拓扑快照 / 传播边按注册全集计算 |
| P2 | NetworkZone 粒度 | 支持按子网/角色配置区域 |
| P2 | Gateways/Neighbors 未采集 | agent 补采集默认网关与 ARP 邻居 |
