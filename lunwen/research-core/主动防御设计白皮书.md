> 版本：2026-08-14（v0.3.0 草案）  
> 状态：设计提案，待评审  
> 原则：严格区分 **已有证据支持的理论/现象**、**方法论支持** 与 **仍需直接验证的推算**，不把假设写成结论。

## 摘要

v0.3.0 的战略定位是：**将 ASSCOR 从"阻断导向的被动防御"升级为"引导导向的主动防御"**。核心是把攻击者模型从流水线中的一个功能模块，升级为整个自动化链路的**认知内核**——持续估计攻击者状态、预测其下一行动概率分布、通过主动观察/欺骗/引导改变可观测性、再利用新情报更新攻击者模型，形成自适应的"攻击者—防御者"闭环。

本白皮书整合了三类材料：

1. **理论基座**（5 篇论文）：决策论规划（I-POMDP²）、博弈论、欺骗技术三域回顾（honeypot/honeytoken/MTD）、MTD 技术综述、攻击图博弈；
2. **攻击者行为模型**（`attacker_model_theory_and_hypotheses_v2.md`，H1–H10 假设与证据等级）；
3. **自动化攻防链路**（`automated_attack_defense_chain_improvement.md`，双闭环 + 证据融合 + 状态引擎 + 引导规划）。

最终回答一个研究问题：

> **AI、共享工具/代码和个人经验如何共同塑造攻击者的行动概率分布，防御者能否利用观测、欺骗和引导主动改变这一分布？**

## 1. 战略定位：从阻断到引导

### 1.1 为什么转向引导

传统防御（防火墙、IPS、杀软、修补）是**阻断嵌入式防御**（block-embedded defense）：用访问控制/隔离使异常状态不可达。它有两个固有缺陷（MTD 综述已论证）：

- **认知局限**：防御者无法枚举攻击者所有潜在路径与全部漏洞，攻击者在左利用阶段（left-of-exploitation）长期侦察的信息优势无法消除；
- **时间不对称**：攻击者可长期规划，防御者必须实时响应，补丁滞后给攻击者留下时间窗口。

引导式主动防御不追求"拦住一切"，而是**制造信息不对等**：用诱饵/假情报让攻击者误判环境，迫使其放弃慢速潜伏、转为快速验证，从而**提前暴露 TTP 与意图**。收集到的情报反哺下一轮更精准的诱饵，形成正反馈闭环：

```text
引导 → 收集 → 分析 → 决策 → 再引导
```

**MITRE Engage 在本体系中是引导工具，而非阻断工具。** 隔离主机（isolate_host）降级为"引导无效/确认高危"时的兜底。

### 1.2 轻量欺骗原则（"够用原则"）

意图驱动的轻量欺骗：无需高逼真蜜凭证。识别攻击者意图后，用轻量蜜罐主动暴露可疑服务或抛出虚假情报即可。攻击者上钩阈值低，只需制造"突破口假象"便能诱其暴露。这直接降低欺骗部署成本，使欺骗可在单主机规模上落地。

## 2. 理论基座

### 2.1 决策论 vs 博弈论：为什么选决策论规划

博弈论（Zhu 教程；Anwar & Kamhoua 攻击图博弈）提供了欺骗的量化框架：信号博弈、动态博弈、机制设计、hypergame、POSG。但博弈论方法的固有困难在于：

- **均衡计算复杂度**：一般和随机博弈求纯策略纳什均衡 PSPACE-hard，POSG 更不可解；
- **对称理性假设**：均衡概念假设双方对称地最优响应，难以刻画攻击者的**主观理性**（信息不对称、有限嵌套建模、认知偏差）。

决策论方法（Shinde & Doshi 的 I-POMDP²）更适合本体系，因为它：

- **显式建模攻击者信念**：防御者维护对攻击者信念/能力/偏好的**主观模型**（models 作为状态空间的一部分）；
- **有限嵌套递归推理**：可模拟"攻击者不知防御者存在"（level 0）与"攻击者推理防御者行为"（level ≥2）两类场景；
- **认知偏差建模**：利用 FAE（基本归因错误）与确认偏差去欺骗**复杂**攻击者——这是博弈论均衡框架无法提供的。

**关键启示**（直接支持 §1 的引导战略）：I-POMDP² 实验观察到 level-3 防御者的精妙策略——**先误导攻击者相信防御是被动的（诱其深度投入），再部署诱饵欺骗之**。这正是"引导而非阻断"的决策论证明。

### 2.2 欺骗分类学与四层欺骗栈

三域回顾（Zhang & Thing）建立二维分类学：

- **三维技术**：honeypot（蜜罐）、honeytoken（蜜标）、MTD（移动目标防御）——三者互补，可组合成编排式欺骗；
- **四层欺骗栈**：network / system / software / data 层；
- **杀伤链映射**：回答"哪些技术破坏哪个攻击阶段、属于哪层栈"。

honeypot/honeytoken 是**假目标**（引入假信息），MTD 是**动态变换**（移除确定信息但不主动误导）。本体系以 honeypot/honeytoken 为主（主动引导），MTD 作为可选的确定性削弱手段。

### 2.3 MTD 设计原则（可选组件）

MTD 综述提炼出五项设计原则，作为将来引入 MTD 组件时的约束：

1. **Coverage**：动态随机变换所有可能被利用的漏洞，优先覆盖关键资源；
2. **Unpredictability**：足够异构冗余组件，保证变换空间；
3. **Timeliness**：变换触发须先于攻击实施；
4. **Superstability**：多机制协同等效于单一更复杂机制，且与现有防御协同；
5. **Functional equivalence**：变换期间业务功能持续可用。

### 2.4 实证威胁态势（2026 DBIR）

攻击者模型必须锚定真实态势，而非先验猜测。2026 DBIR（31,000+ 事件，22,000+ breach，145 国）关键数据：

| 指标 | 2026 报告值 | 趋势 |
|------|:---:|------|
| 漏洞利用成初始访问第一 | 31% | 较上年 20% 增长 55% |
| 凭据滥用 | 13% | 较上年 22% 下降（部分因 Pretexting 单列） |
| 勒索软件占 breach | 48% | 上年 44%，持续上升 |
| 第三方参与 breach | 48% | 较上年 30% 增长 60% |
| KEV 完全修复率 | 26% | 上年 38%，下降 |
| KEV 修复中位时间 | 43 天 | 上年 32 天，恶化 |
| Human element 参与 | 62% | 上年 60% |
| Social Engineering 模式 | 16% | 第三常见 breach 模式 |
| Pretexting 作初始访问 | 6% | 语音/短信，同步社会工程 |
| GenAI 辅助攻击 | 中位 15 技术 | 最高 40–50 技术 |

**三条方法论约束**（直接进入 §6 数据模型）：

1. **sampling/reporting bias**：breach 未必被报告、公开事件更易入集、样本丰富类型被过度代表。知识库必须保留 `Source / SourceType / CollectionTime / Confidence / Provenance`，不能"出现 100 次 = 真实概率 100 倍"；
2. **技术分布依赖数据源**：同一技术（如 T1003 OS Credential Dumping）在 threat intelligence vs incident 数据集中比例差异显著，不能把单一来源当"真实总体"；
3. **社会工程战略价值 ≠ 频率**：其价值应由带来的 Information/Identity/Trust Gain 衡量，而非事件占比。

## 3. 攻击者模型（H1–H10）

> 本节合并 `attacker_model_theory_and_hypotheses_v2.md`，以 v2 的 H2a/H2b 拆分与证据等级表为准。

### 3.1 模型目标

目标不是"预测下一步哪个 ATT&CK Technique"，而是建立：

```text
Observation → Attacker State Estimation → Intent/Capability/Experience/Belief
            → Likely Action Distribution → Engagement/Deception
            → New Evidence → State Update → Repeat
```

### 3.2 Attacker State 结构

```text
AttackerState
├── Capability        实际可执行能力集合
├── Experience        过去成功/失败形成的经验
├── Intent            当前阶段目的（Recon/Credential/Lateral/DataTheft/WebAttack）
├── TTP_Repertoire    熟悉/可调用的 TTP 子集
├── SharedCapability  公共工具/共享代码/公开知识/地下生态/AI 提供的能力
├── IndividualCapability  自身经验/目标知识/习惯/基础设施
├── AI_Dependence     ∈[0,1] 决策/执行对 AI 的依赖度
├── TargetKnowledge   对当前目标已知程度
├── BeliefState       对目标环境的主观认知
└── Objective         最终目标
```

### 3.3 假设与证据等级

| 编号 | 命题 | 状态 | 证据等级 |
|---|---|---|---|
| H1 | 成功经验提高相关 TTP 复用概率 | 待直接验证 | ★★★☆☆ |
| H2a | IT 技能与黑客效率正相关 | 学术实证支持 | ★★★★★ |
| H2b | 能力/经验提高已验证 TTP 依赖 | 进一步推论 | ★★★☆☆ |
| H3 | 攻击者会寻求 Initial Advantage | 多源支持 | ★★★★☆ |
| H4 | 社工战略价值不能由频率单独衡量 | 方法论/案例支持 | ★★★★☆ |
| H5 | 存在 Shared Capability Layer | 直接证据 | ★★★★★ |
| H6 | AI 扩大共享能力可获取性 | 强支持 | ★★★★★ |
| H7 | AI 导致 Strategy Convergence | 待验证核心假设 | ★★☆☆☆ |
| H8 | 有效能力与策略多样性独立 | 理论推算 | ★★★☆☆ |
| H9 | 高经验可抵消 AI 收敛 | 待验证 | ★★☆☆☆ |
| H10 | 应预测 Action Distribution | 方法论支持 | ★★★★☆ |

### 3.4 关键机制

**Initial Advantage（H3）**：攻击者优先降低目标不确定性，而非直接技术突破。优势不仅指已获权限，还包括 Identity/Trust/TargetKnowledge/Relationship/Credential/Environmental Information：

\[
InitialAdvantage = f(InformationGain,\ IdentityGain,\ TrustGain,\ AccessGain)
\]

\[
Information/Identity\ Gain \downarrow Target\ Uncertainty \uparrow Expected\ Success\ of\ Later\ Actions
\]

**Shared Capability（H5/H6）**：攻击者能力空间存在公共子集（共享工具/代码/AI），因此：

\[
Capability_i = SharedCapability + IndividualCapability_i
\]

关键推论：`Observed Similarity ≠ Same Actor`。归因必须先排除公共工具/共享代码/通用 TTP/共享基础设施/AI 生成策略。

**Strategy Convergence（H7，核心待验证假设）**：

\[
AI\ Dependence \uparrow \Rightarrow CrossAttackerDistance \downarrow\ ?
\]

AI 降低能力门槛，但因模型倾向提供高概率常见方案，不同攻击者可能更多从共同策略集选择。需实验验证 AI-assisted vs human-only 攻击者在 TTP entropy、序列多样性、行为距离、策略簇分布上的差异。

**有效能力与策略多样性分离（H8/H9）**：

\[
EffectiveCapability = f(HumanSkill,\ Experience,\ Tools,\ AI)
\]

\[
StrategyDiversity = f(Experience,\ AI\_Dependence,\ TargetKnowledge,\ SharedCapability)
\]

低经验攻击者高采纳 AI 建议→策略收敛；高经验攻击者选择性采纳→潜在发散。

### 3.5 明确不能提前写成结论

1. 能力越高一定越依赖自己的 TTP；
2. 高能力攻击者一定更喜欢社会工程；
3. 社会工程一定是所有场景的第一初始访问技术；
4. AI 一定降低攻击行为熵；
5. AI 一定使不同攻击者执行相同路径；
6. APT 代码相似就意味着同一攻击组织；
7. 地下社区观察可以代表全部攻击者；
8. 某个 TTP 出现次数可以直接作为真实成功概率；
9. 概率模型一定比确定性模型预测准确；
10. 任意一种具体概率模型一定优于其他模型。

## 4. 预测模型：从 Next TTP 到 Action Distribution

### 4.1 为什么不做确定性预测

实证研究显示真实攻击行为非线性、路径变化、不严格按固定 Kill Chain 顺序。`TTP₁ → TTP₂ → TTP₃` 单一路径确定性预测不足以覆盖真实行为。

### 4.2 预测目标

\[
P(A_{t+1}\mid AttackerState_t,\ TargetState_t,\ Observation_t)
\]

而非 `NextTTP = X`。模型同时输出：

```text
Most Likely / Most Beneficial / Worst Case / Most Dangerous / Most Observable / Most Deceptive
```

### 4.3 两层模型（保留 ATT&CK）

\[
P(TTP_i) = \sum_j P(TTP_i\mid Action_j)\ P(Action_j)
\]

ATT&CK 不被替代，而是作为"攻击行为语义层"：

```text
Attacker State → Action Distribution → ATT&CK TTP Distribution
```

## 5. 自动化攻防链路

> 本节整合 `automated_attack_defense_chain_improvement.md`。

### 5.1 双闭环

**防御闭环**（既有）：

```text
探测 → 定位 → 响应 → 报告 → 阻断 → 修复 → 验证 → 重定位 → 归档 → 循环
```

**攻击者认知闭环**（新增）：

```text
观测 → 状态估计 → 行为预测 → 引导/欺骗 → 攻击者响应 → 新情报 → 状态更新 → 再次预测
```

### 5.2 Evidence Fusion

SSAM/ATT&CK/日志/网络/诱饵触发/威胁情报/事件历史不直接进预测器，先融合：

```text
Evidence { Source, SourceType, Timestamp, Actor, Intent, Action, TTP, Target, Confidence, Provenance }
```

### 5.3 Multi-layer Temporal Graph

单纯 `Host─connects─Host` 不足以描述攻击者/身份/工具/代码/TTP/证据。建立多层时序图：

- **Network Layer**：Host/Service/Subnet/Gateway/Internet
- **Dependency Layer**：Service→Service
- **Identity Layer**：User/Account/Credential/Role/Privilege
- **Attacker Layer**：Actor/ActorCluster/Campaign/Infrastructure
- **Capability Layer**：Tool/Code/TTP/Exploit/AI Capability
- **Evidence Layer**：Observation/Event/Alert/DecoyTrigger/Incident

关系如 `ATTACKER─uses→TOOL─implements→TTP─produces→ACTION─produces→OBSERVATION→EVIDENCE`，支持计算 Capability Centrality / Capability Reuse / TTP Sharedness / Actor Similarity。

### 5.4 Attacker State Engine

SRD 作为动态状态演化层，状态更新：

\[
OldState + Evidence \rightarrow State\ Update \rightarrow NewState
\]

### 5.5 Engagement Planner（IntentGuider 升级）

从"根据意图部署诱饵"升级为"选择最大化新情报获取量的干预"。候选干预按效用排序：

\[
Utility(E) = \alpha\ IG(E) + \beta\ DP(E) + \gamma\ AV(E) - \delta\ Risk(E)
\]

其中 IG=Information Gain，DP=Detection Probability，AV=Attribution Value，Risk=风险，Exposure=暴露。

### 5.6 诱饵传感器化

诱饵不只记录 `Triggered=true`，而是完整交互链（假 SSH 为例）：

```text
连接 → 尝试账号 → 尝试凭据 → 执行命令 → 系统发现 → 连接其他服务
```

每条记录 Timestamp/Source/InteractionType/CredentialAttempt/Command/Sequence/FollowUpAction/TTP/Outcome。**Deception Object = Sensor + Control Point**。

### 5.7 验证后重定位

修复不是终点。`修复 → 验证 → 重建目标状态 → 重建攻击者状态 → 重算攻击面 → 重算行动分布 → 重定位`。验证是下一轮预测的输入。

### 5.8 预测置信度驱动的策略

```text
Confidence Low  → 优先收集情报
Confidence High → 允许更主动的 Engagement
```

## 6. 数据需求（支撑 H1–H10 验证）

情报记录至少保留：

```text
Evidence
├── Source / SourceType / Timestamp
├── Actor / ActorCluster
├── Target
├── Intent / Action / TTP / TTP Sequence
├── Tool / Shared/Public Tool? / Shared Code?
├── AI Assistance?
├── Experience Proxy / Capability Proxy
├── Target Knowledge
├── Information Gain / Identity Gain / Trust Gain
├── Outcome
├── Confidence
└── Provenance
```

**特别不能只保存 `Actor → TTP`**，而应保存 `Actor → Context → Intent → Available Capability → Selected Action → TTP → Outcome → Next Action`，否则无法验证"经验导致行为选择"或"AI 导致策略收敛"。

## 7. 认知建模：FAE 与确认偏差的落地

I-POMDP² 论文的认知建模直接支持 §1 的引导战略，并给出可落地的量化方向：

- **FAE（基本归因错误）**：攻击者受 FAE 影响时，将观测归因于防御者类型而非环境状态（粗粒度建模）。理性防御者可利用此偏置欺骗攻击者对其"类型"（如被动 vs 主动防御者）的判断——对应 §2.1 中 level-3 防御者"先伪装被动再欺骗"的策略。
- **确认偏差**：攻击者高估符合其既有信念的证据、低估矛盾证据。防御者可据此维持攻击者的错误信念，延长其在蜜罐中的投入。

这两个偏差在 v0.3.0 中作为**可选认知层**接入 Attacker State 的 BeliefState 更新，初期用规则+权重近似，不引入完整 I-POMDP² 求解器（其代价高昂）。

## 9. 理论核心与待验证问题

### 9.1 最稳固的理论核心

```text
ATT&CK（行为标准化） + 多源 CTI（Evidence） + Attacker State（Intent/Capability/Experience/Belief）
    + SRD（动态演化） + Engage/IntentGuider（改变感知环境、获取新证据）
```

### 9.2 最具原创潜力、最需实证验证的部分

```text
Shared Capability + AI Assistance → Strategy Convergence?
    → Attacker Predictability → Probability Distribution
    → Active Engagement → New Evidence → State Update
```

### 9.3 最终研究问题

> **AI、共享工具/代码和个人经验如何共同塑造攻击者的行动概率分布，以及防御者能否利用观测、欺骗和引导主动改变这一分布？**

这比单纯"预测下一步 ATT&CK Technique"更接近本系统的真正理论核心。
