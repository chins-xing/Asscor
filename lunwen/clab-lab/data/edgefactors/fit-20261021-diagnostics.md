# 拟合诊断：设计矩阵、可辨识性与重抽样单位（Task 24 Step 2）

> 产物对：`fit-20261021.md`（工具输出，`-group-by scenario`）、`params-20261021.ini`、
> `params-20261021-factors.ini`、`compare-20261021.md`、`compare-20261021-rpt-targeted.md`。
> 本文件是**独立复算**的诊断证据（不是工具输出），脚本 `build/fit24/analysis.py`（`build/` 是
> gitignored，故把**结论与原始输出**落在这里归档）。
>
> 复算口径逐条对齐仓内实现（不抄任何报告）：折叠 = `edgefactor.CollapseToFactors`（按规范 ID 取
> `EffectiveFactor` 最小者、并列取先出现）；生效因子 = `EffectiveFactor(f,c)`（`c=0 ⇒ 1`、`c≥1 ⇒ f`）；
> 设计矩阵 = `fit.go:design`（列 = 截距 + 7 个主效应 `a_i` + 5 条先验边 `a_i·a_j`，
> `a_i = (1−eff_i)·Σ_d v_i[d]`，`D = DefaultDomains ∩ λ` = 5 个默认域，未激活的因子该行为 0）；
> 向量取 `configs/edgeexp/graph.ini` 的 `[edge_factors.model]`。
>
> **一句话结论**：主批 22 条 targeted 记录只给出 **5 个逐位不同的设计行**，而每个行都**同时**带着
> `compromised=1` 与 `0`（两臂同读数、标签相反）⇒ 设计矩阵秩 5 < 参数 13，logistic
> 似然的最优点是**精确的 `β = 0`**。这不是"求解器失败"，是"这套设计无法辨识任何系数"。
> VIF 的口径见 §2：**11 / 12 个非截距列 VIF = ∞**；`EF-3FA` 是有限值 **1.090909 = 12/11**
> （它只在 2 条记录非零、仍不足以支撑可用估计）——**秩亏 ≠ 每列都 ∞**（第二次审计 Important-1）。

## 3. 为什么点估计恒为 0（结构性原因，不是求解器失败）
  每个设计行的重数与标签分布（{标签: 条数}）：
    重数=10  标签分布={1: 5, 0: 5}
    重数= 4  标签分布={1: 2, 0: 2}
    重数= 4  标签分布={1: 2, 0: 2}
    重数= 2  标签分布={1: 1, 0: 1}
    重数= 2  标签分布={1: 1, 0: 1}
  ⇒ 每个 x 都在似然里**同时**出现 y=1 与 y=0 ⇒ 梯度方程 Σ(y−σ(w·x))x = 0 被 w = 0 满足；
     L2 罚项让 0 成为**唯一**最优点。
  ⇒ 拟合出的 β 全为 0、5 条先验边全部按「β ≤ 0 ⇒ 不写」被移除 —— 这不是『耦合为 0』的证据，
     是『这套设计无法辨识任何系数』的证据（同一 x 同时是两类标签）。
  推论（决策层）：同一实例两臂的分数必然相同（打分输入逐字段相同、模型是确定性函数），
     故任何判定线要么把两臂一起放行、要么一起阻断 ⇒ 一致率**上限就是 0.5**，与候选无关。

## B. 交叉验证口径的三次运行（同一份主批数据、同一个 `-seed = 20261021`）

| 运行 | 重抽样单位 | 折数 | CVErr | 点估计 |
|---|---|---|---|---|
| `fit-20261021-rowlevel.md` | 逐行 | 3 | **3.491897** | β 全 0 |
| `fit-20261021.md`（**权威产物**） | 按实例 | 3 | **0.693147** (= ln 2) | β 全 0 |
| 留一实例（LOIO，`-folds 11`） | 按实例 | 11 | **0.693147** (= ln 2) | β 全 0 |

读法（**重要**）：

- `0.693147 = ln 2` 正是**常数预测器**（对每条都报 p = 0.5）的对数损失 ⇒ 按实例切折时，模型对
  **没见过的实例**没有任何预测信息。这是"真实泛化能力 = 0"的诚实读数。
- 逐行的 `3.491897` **不是**"泛化很差"，而是**病态**：同一实例的另一臂（同一 x、相反标签）就在
  训练集里 ⇒ 训练出来的模型对验证集那条同胞给出**自信的错答**，对数损失被推高。把它当泛化误差
  读，方向都对不上。这就是 Task 24 Step 2 要求"必须按实例重抽"的实测理由。
- 三种口径的点估计**逐位相同**（全 0）—— 重抽样单位只影响 CVErr 与自助法区间，不影响 MLE。
  按实例的自助法区间是 `[0, 0]`（每次重采样的解都是 0）；逐行的区间宽达 ±10² 量级（病态解在
  噪声方向上的抖动），**不能**当参数不确定度读。

## C. 两条拟合纪律的实测核对

1. **`-l1` 默认关闭，且不得用它"解释边强度"**：本次权威运行 `-l1 0`。另跑一次 `-l1 0.05`
   （`build/fit24/fit-l1-005.out`，逐行口径）：CVErr 由 3.491897 变 **1.174674**，而
   **点估计仍全为 0**（`w = 0` 已是无罚目标的最优点，罚项无从再推高任何系数）。说明在本设计上
   "L1 让耦合变小/变大"这种读法**连方向都无从建立**；与 Task 10 在共线合成夹具上实测的
   "中等 L1 反而推高耦合系数（0.453 → 0.664 → 0.918）"一起构成纪律依据。
2. **不得为迁就实现而放宽偏置阈值**：`TestFitCouplingIsUnbiasedAcrossSeeds` 的 `0.08` 与
   `fitDefaultL2 = 0.01` **本次一个字都没动**（该用例在 `fit_test.go` 里零改动、且全绿）。
   本任务没有"为了让绿灯回来"而调过任何阈值。

## E. 这份诊断不能证明什么（边界）

- 它证明的是**这批数据**的设计矩阵秩亏（5 个不同 x vs 13 个参数），不是"耦合不存在"。要把
  耦合并辨识性做出来，需要**每实例独立**的读数跨场景变化（即镜像更多 S2/S3 组合的 targeted 臂），
  而不是更多同一姿势的重复。
- VIF/条件数是对**当前** 22 行、7 主效应 + 5 边的设计算的；换边集或换主效应集合都会变，
  故不可外推成"这些边永远不可辨识"。
- 逐条离线分数**没有**导出成独立产物（工具不提供 per-record 分数转储）。"两臂分数相同"这一结论
  由"打分输入除 ts 外逐字段相同 + 模型对输入是确定性函数"给出，并用四候选"一致率恰好 0.500"
  侧面印证；若将来需要逐条分数证据，得给工具加一个 verbose 转储（未做，列入未跑清单）。
