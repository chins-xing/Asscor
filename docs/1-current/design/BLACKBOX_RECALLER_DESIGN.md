# 黑盒阵列可选扩展方案（七轮审计收敛归档）

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 架构决策归档

---

## 一、决策摘要

经过七轮审计，最终架构决策：

> **黑盒阵列（AI 模型）不能作为主方向，只能作为可选扩展；内核与扩展体系进行最小化修改；白盒确定性探测通道保持为主路径 + 兜底。**

---

## 二、七轮审计收敛历程

| 轮次 | 审计主题 | 核心结论 |
|:---:|------|------|
| 1 | 黑盒+白盒混合架构可行性 | 划分原则正确；守住"黑盒不直接驱动决策"红线 |
| 2 | 多算法编排器 + 黑盒 | `RoleAdvisory` 已定义但合并逻辑未区分角色；`MergeWorstOf` 成最大破坏源 |
| 3 | 多黑盒阵列初步筛选 | "召回层+精确层"两阶段架构；破坏面积降至零 |
| 4 | 四约束（判断依据/全票丢弃/扩展包/性能体积） | C4 性能体积是压倒性约束；扩展包与常驻仲裁逻辑冲突 |
| 5 | 轻量内核阵列 + 重型分布式阵列 | 部署形态细化；内核零膨胀（独立二进制）；降级路径 |
| 6 | AI 模型自身安全性 | 揭示"黑盒善意"隐含假设；AI 是新兴未成熟攻击面 |
| 7 | 权限限制 + 直接攻击防御 | 三层防御（进程隔离/最小权限/单向数据流）；逻辑后门+提示注入不可防 |

**收敛核心**：黑盒输出本质是"不可形式化验证的信任边界"，必须始终视为不可信输入，由白盒确定性验证兜底。

---

## 三、最终架构定位

```
┌─────────────────────────────────────────────────────────────┐
│  白盒探测通道（主路径，现有 76 扩展点，默认启用，不变）      │
│                                                              │
│  原始数据(心跳/适配器/日志)                                   │
│      │                                                       │
│      ├─ 确定性评分（SSAM/Prism 纯函数）                       │
│      ├─ 策略引擎（确定性阈值状态机）                          │
│      ├─ 定位聚合（ATT&CK 归因 + SRD 传播路径）                │
│      ├─ 阻断/修复/验证（扩展点 + 第三方）                     │
│      └─ 归档（HMAC 签名审计）                                │
└─────────────────────────────────────────────────────────────┘
                        │ 候选信号（仅当扩展启用）
                        ▼
┌─────────────────────────────────────────────────────────────┐
│  黑盒阵列（辅助召回，可选扩展，默认不编译不部署）              │
│                                                              │
│  [轻量阵列] ──召回──→ [重型阵列] ──精确──→ 候选信号            │
│    (决策树/规则)      (深度学习/Transformer)                   │
│     跟随内核同机          分布式部署                          │
│                                                              │
│  ── 发布 → recaller.candidates → 白盒复核 → 确定性决策        │
└─────────────────────────────────────────────────────────────┘
```

## 五、关键不变式

| # | 不变式 | 说明 |
|:--:|------|------|
| 1 | **默认纯白盒** | 黑盒阵列默认不编译、不部署，纯白盒是默认形态 |
| 2 | **白盒主路径** | 启用黑盒后，白盒探测通道仍为主路径 + 兜底 |
| 3 | **黑盒不可信** | 黑盒输出视为不可信输入，白盒复核后才进决策 |
| 4 | **一键降级** | 黑盒异常时移除扩展即回纯白盒模式 |
| 5 | **零信任黑盒** | 黑盒输出与攻击载荷同等对待，严格白盒验证 |

## 六、黑盒阵列约束（若未来启用）

| 约束 | 要求 |
|------|------|
| 判断依据 | 黑盒输出必须带详细判断依据 + 置信度 |
| 全票丢弃 | 仅所有黑盒一致判定"噪声"才丢弃 |
| 权限限制 | 进程隔离 + 最小权限 + 单向数据流 |
| 模型安全 | 禁用 pickle、权重签名、算子白名单 |
| 可解释优先 | 决策树/规则型优先，深度模型仅实验 |

---

## 七、实施优先级

| 优先级 | 事项 | 依赖 |
|:---:|------|------|
| P0 | 白盒探测通道保持（无需改动） | 无 |
| P1 | 3 个 `recaller.*` 扩展点 | 内核最小修改 |
| P2 | `MergeWhiteboxFirst` 策略 | multi-algo-orchestrator |
| P3 | 黑盒阵列 build-tag 模块（可选） | P1 + P2 |

**核心原则：P0 永远可用（纯白盒），P1-P3 是渐进式可选的增强。**
