# 第 20 章 — 工程哲学

架构先于功能——功能代表即时价值，架构代表长期可持续性。简单优于复杂——在适用竞争方案的地方，更简单的方案应被偏好。分离优于耦合——基础设施与推理之间的分离是项目最宝贵的架构原则。

设计模型而不只是代码——概念模型提供架构框架。没有模型，实现变得仅由便利驱动。长期系统通过连续改进而非周期性重写而存活。

文档是架构的一部分——架构存在于代码中也存在于文档中。评估模型是近似的——分数的目的是提供决策支持，而非替代判断。

Goodhart 定律（当一个指标成为目标，它就不再是一个好的指标）以特殊的力量适用于安全评分。平台的哲学立场是分数应提供信息，而非自动化决策。
