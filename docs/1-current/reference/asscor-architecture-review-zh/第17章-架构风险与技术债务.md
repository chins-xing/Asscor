# 第 17 章 — 架构风险与技术债务

最大的架构风险是无控制的增长。增长应通过扩展架构而非扩展现有组件来发生。内核代表运行时最稳定的部分——因此也是最容易受到责任积累影响的组件。

插件接口过于频繁的变更增加集成成本，非向后兼容的变更可能破坏现有插件。架构的一致性依赖于概念层次保持完整——当一个关注泄漏到另一个关注中时，出现了概念层违规。

当前代码库中存在几个重复模式——错误处理、资源管理、配置解析、日志模式。测试覆盖有限，特别是在内核服务、证据处理管道和事件分发中。配置定义与实际运行时行为之间存在漂移风险。

随着平台演进，新增的工程概念可能与原始概念模型产生紧张——当新概念引入新的架构维度时，需要重新形式化以适应扩展。
