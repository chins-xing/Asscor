# 第 12 章 — 事件总线架构

随着运行时增长，独立组件必须交换信息而不形成紧密耦合。Asscor 引入事件驱动的通信模型——子系统通过事件总线通信而非直接调用组件。

通信模式：组件 A → 事件总线 → 组件 B、组件 C、组件 D。发布者不知道谁消费事件，消费者不知道谁发布了事件。

每个事件遵循相同的生命周期：创建 → 发布 → 分发 → 处理 → 完成。事件分为几类：运行时事件（启动/停止）、生命周期事件（服务注册/插件加载）、评估事件（开始/完成/失败）、配置事件（重载/策略更新）、健康事件（健康/故障/降级）。

每个事件应包含统一元数据：ID、类型、时间戳、来源、载荷、元数据。事件总线仅应执行路由——订阅者管理、分发、过滤、排序。不应执行业务逻辑。

应避免的风险：事件中的业务逻辑、事件爆炸（发布过多事件增加复杂度）、循环事件（事件触发事件无限循环）。随着平台增长，事件总线可支持远程订阅者、分布式运行时、持久事件存储。
