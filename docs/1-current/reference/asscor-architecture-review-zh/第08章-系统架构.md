# 第 8 章 — 系统架构

Asscor 应被理解为分层执行架构：用户 → CLI/API/仪表盘 → 决策层 → 评估引擎层 → 证据处理层 → 插件/提供者层 → 运行时基础设施层 → 操作系统/云。

各层职责：运行时层负责生命周期管理、调度、依赖注入——从不直接执行安全评估；插件层提供证据收集、集成——不应包含运行时逻辑；证据层负责归一化、验证、可追溯性；评估层执行推理，引擎保持可互换；决策层将结果转化为运行建议（可接受、受限、不可接受）；呈现层不应包含评估逻辑。

完整评估流水线遵循单向数据流：收集 → 证据 → 评估 → 决策 → 呈现。依赖方向始终向下——呈现 → 决策 → 评估 → 证据 → 插件 → 运行时。反向依赖应当避免。

不同架构层以不同速度演进。稳定层（运行时、证据模型、评估模型）应保护频繁变化的层（规则、知识、策略、威胁情报）。架构自然支持水平扩展——添加新插件、新评估引擎、新报告格式而无需修改现有运行时基础设施。

架构风险包括内核膨胀、层泄露、接口不稳定、概念漂移。未来应通过扩展现有能力而非重组层次来演进。
