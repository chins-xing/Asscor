# 第 7 章 — 证据架构

安全评估始于证据。Asscor 将证据视为整个评估过程的基础，引入了一种面向证据的架构，将数据获取与安全推理分离。

在 Asscor 中，证据被定义为"描述信息系统当前状态的可观察安全事实"。证据应满足：可观察、可复现、可追溯、可解释。证据不应包含运行决策——它为后续推理提供事实性输入。

每个证据对象包含四个逻辑元素：主体（评估目标）、观察（观察到的安全事实）、元数据（时间戳、置信度、上下文信息）、来源（证据起源）。证据在运行时内遵循自身的生命周期：收集 → 归一化 → 验证 → 存储 → 评估 → 归档。

不同工具以不同方式描述相似的观察——归一化将异构输出转化为一致的内部表示，极大简化了下游推理。证据应保持独立于评估引擎——相同证据可被 SSAM、SRD、未来概率模型、AI 辅助推理引擎消费。

证据自然分为几类：配置证据、暴露证据、运行证据、威胁证据、信任证据。未来实现可考虑证据质量属性——置信度、新鲜度、完整性、可靠性。每个评估结果应可追溯回产生它的证据——决策 → 评估 → 证据。

随着 Asscor 演进，证据可能成为生态系统中的共享语言——各组件交换标准化的证据对象，而非特定扫描器的输出。
