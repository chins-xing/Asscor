## 一、概述

熵扩展包（Entropy Extension Pack）由**行为熵、网络熵、基线熵**三个维度组成，输出**当前状态相对零点（基线）的瞬时偏移量**，作为独立结果对外发布，**不进入评分体系**。除读取既有链路的 SSAM/SRD 分数与原始情报外，另设**独立收集器**采集主机行为节奏、网络交互面、日志事件流、资源压力时序四类情报。熵包必须具备时间维度感知能力与全面可审计性，并强化情报存储的保密性、完整性与可用性。

## 二、边界与不变量

1. **单向只读**：熵包读取 SSAM/SRD 分数（含置信区间）、原始情报、心跳/检查/拓扑、自采帧；**不写回评分链**。`internal/engine`、`internal/assessor`、`internal/predictor` 不依赖熵包；熵包不修改 `model.AssessmentResult`。
2. **评分非回归**：启用或停用熵包，评分结果必须**逐位不变**（硬性验收指标，见 §十）。
3. **读数语义**：读数为瞬时熵相对基线的偏移，**可升可降**（不设单调性约束）。
4. **未标定语义**：尚未打点时状态为 `uncalibrated`，读数为 `null`，**绝不输出 0**（0 会被误读为"与基线完全一致"）。
5. **零点唯一**：基线即零点；无自动学习期，仅由管理员经 CLI 打点建立；重置 = 重新打点，且打点/重置进入审计链。
6. **完全独立输出**：熵读数只出现在独立输出面（CLI、导出包、熵事件），**不进任何评分报告**。
7. **存储不可回改**：不提供单帧删除/修改接口，仅按保留策略滚动，滚动动作自身记入审计。

## 四、三熵算法规范

### 4.1 特征归属

| 维度 | 覆盖特征 | 基线 |
|---|---|---|
| 行为熵 `H_b` | 主机行为节奏（进程/服务启停、登录会话、文件完整性哈希变化）+ 日志事件类型分布 | `B_b` |
| 网络熵 `H_n` | 网络交互面（连接五元组、监听端口、协议分布） | `B_n` |
| 基线熵 `KL_0` | 资源压力时序（CPU/内存/IO/负载）+ 既有链路情报（SSAM/SRD 分数与置信区间、CTI 源、拓扑事件） | `B_0` |

三维为**特征归属划分**（互不重叠），而非同一数据的三种读法。

### 4.2 计算链

对每一维度、每一时间尺度：

1. **符号化**：特征离散化为符号集 `S`（枚举型原样映射；连续型按配置分箱，默认等宽 8 箱）。维度符号空间上限 `N = |S_max|` 取**配置的固定上限**，不随窗口内观测数变化（避免归一化除数抖动）。
2. **窗口分布**：窗口 `W` 内统计频率 `p_i = count_i / Σcount`，`Σp = 1`。
3. **归一化熵**：`H = -Σ p_i·log₂ p_i`，`Ĥ = H / log₂ N`，取值 `[0,1]`。
4. **相对零点（双读）**：
   - `ΔH = Ĥ(now, W) − Ĥ(base, W)`，归一化熵之差（无量纲，取值 `[-1,1]`），可正可负（正 = 比基线更混乱/更不可预测）。
   - `KL = Σ p_now,i · log₂(p_now,i / p_base,i)`，非负，偏离越大越高、回归基线则趋 0。
   - 平滑：`p_base,i = 0` 时以 `ε = 1e-6` 替代（Laplace 型平滑），防对数发散。
5. **输出四量**：`Ĥ_now`、`Ĥ_base`、`ΔH`、`KL`。行为/网络维以 `ΔH` 为主读，基线维以 `KL` 为主读；四量全部进结果供上层选读。

### 4.3 多尺度与时间感知

| 项 | 默认 | 说明 |
|---|---|---|
| 尺度 | `short = 5m`、`mid = 1h`、`long = 24h` | 每尺度独立分布与四量读数，可配 |
| 采样节拍 | 10s | 熵帧采集周期，与心跳解耦，可配 |
| 变化率 | 短窗 `ΔH` 序列的最小二乘斜率 | 单位：归一化熵/分钟，反映"变化快慢" |
| 持续时长 | 连续超出阈值的累计时长 | 区分"尖峰一闪"与"持续漂移" |
| 基线年龄 | `now − baseline.ts` | 陈旧基线会让读数失真，必须显式输出 |
| 采样完整度 | 实收帧数 / 应有帧数 | `gap` 显式化，不插值伪造 |

**阈值告警**（默认，可配）：`|ΔH| > 0.15` 或 `KL > 0.25` 且持续 `≥ 10min` → 产出"熵事件"（hook `entropy.threshold.exceeded`），仅作为独立事件，不回流评分。

### 4.4 时间戳处理

- 帧时间戳为 UTC；同时记录单调时钟读数以计算单调差，检测**时钟回拨**。
- 回拨超过阈值（默认 1s）→ 记审计事件并把受影响帧标记 `clock_skew`。
- 窗口判定按时间戳而非到达顺序；乱序到达帧进入对应时间窗，重复帧按 `(host_id, seq)` 幂等去重。

## 五、独立收集器规范

### 5.1 采集面与最小化原则

| 采集面 | 采集内容 | 明确不采 |
|---|---|---|
| 主机行为节奏 | 进程/服务启停事件、登录会话进退、关键路径文件哈希变化**标记** | 文件内容、命令行参数明文 |
| 网络交互面 | 连接五元组（对端 IP 可哈希）、监听端口、协议计数 | 载荷、DNS 查询内容 |
| 日志事件流 | 事件速率与类型分布 | 原始日志行（仍走既有 `internal/collector` 链） |
| 资源压力时序 | CPU/内存/IO/负载采样 | 进程级敏感明细（可配） |

- 默认开启进程名/路径与对端 IP 的**哈希化**（HMAC 化，配置可关）。
- agent 侧实现为 Linux（`/proc` 解析）+ 非 Linux stub（编译不失败但只上报 `unsupported`）。

### 5.2 传输与隔离

- 熵帧经**独立通道**上报：复用已认证的 mTLS 通道，但使用独立 RPC 方法与独立节流/背压，不与心跳共用队列。
- kernel 侧独立 goroutine 池 + 超时；熵采集阻塞或失败**不得影响心跳与评分**。
- 缺失显式记录 `frame.gap`（起止时间、原因），完整度随之下调；**不插值、不外推**。
- 采集开关、节拍、哈希化策略均来自 config（`[entropy]` 段），配置变更记审计。

## 六、存储与 CIA 规范

### 6.1 目录布局（权限 0700，文件 0600）

```
<DataDir>/entropy/
  keys/entropy-frame.key        帧加密密钥（32B 随机，独立密钥域）
  keys/entropy-chain.key        链头 HMAC 密钥
  frames/0000NN.log             加密帧日志（append-only，按大小滚动）
  chain/index.jsonl             逐帧哈希链索引（加密）
  chain/head.json               链头（帧号范围 + HMAC 签名 + 时间）
  baseline/current.json         当前基线快照（加密）
  baseline/history/<ts>.json    历史基线归档（每次打点一份，永久保留）
  audit/audit.jsonl             审计事件（加密，append-only）
  export/                       离线导出包（临时产物，导出后清理）
```

### 6.2 保密性

- **落盘即加密**：帧、链索引、基线快照、审计日志写入前加密，复用 `securemode.Encrypt`（argon2id KEK + AES-GCM 信封）。
- **自持独立密钥域**：帧加密密钥与链头签名密钥均由熵包自持，**不与 `securemode`/`integrity` 共享**；首次初始化生成（0600）并记 `key.init` 审计。
- 目录 0700、文件 0600，写入走"显式 `chmod` 后再 rename"路径（沿 RC-L2 范式，防宽松 umask 放宽权限）。

### 6.3 完整性

- **逐帧哈希链**：`hash_n = SHA256(prev_hash ‖ frame_no ‖ ts ‖ ciphertext)`，任何插入/删除/重排都会破坏链。
- **链头签名**：每 N 帧（默认 256）或每 T 分钟（默认 5min，取先到者）用熵包链密钥做 HMAC-SHA256 签名，写入 `chain/head.json`。
- **交叉锚定**：审计链头与数据链头互相记录对方哈希，防止"只裁剪其中一条链"。
- **校验时机**：启动时快速校验链尾；`verify` 命令做全链校验（检测截断/重排/篡改）；校验结果记审计。

### 6.4 可用性

- **原子写**：`tmp → chmod 0600 → fsync(file) → rename → fsync(dir)`；崩溃残留下次启动清理。
- **崩溃恢复**：尾部半帧或半条审计记录被截断时，截断至最后一个完整记录并记 `frame.gap` + 审计；已加密帧不重写。
- **保留策略**：原始帧默认滚动 30 天；聚合读数、基线历史、审计事件**永久保留**。
- **导出/备份**：`export` 生成离线包（帧哈希序列 + 链头 + 基线元数据），供第三方核验哈希链自洽与存在性（第一版为 HMAC，外部无法验证 MAC，仅管理员可本地 `verify`）。

## 七、可审计性规范

### 7.1 事件类型

| 事件 | 触发 |
|---|---|
| `baseline.snapshot` | 管理员打点（含操作者 uid/pid、快照内容哈希、窗口元数据、前一基线哈希） |
| `baseline.reset` | 管理员重置（= 新打点，含重置原因字段） |
| `key.init` | 熵包密钥域初始化 |
| `frame.gap` | 采集缺失（起止、原因） |
| `clock.skew` | 时钟回拨超阈值 |
| `chain.head.signed` | 链头签名（帧号范围、签名值） |
| `retention.roll` | 保留策略滚动删除（删除范围、删除前链头哈希） |
| `integrity.check` | 链校验结果（范围、结果、失败位置） |
| `export` | 导出请求（范围、内容哈希、目标路径） |
| `access.denied` | 未授权访问/非管理员尝试高危操作 |
| `config.change` | `[entropy]` 配置变更 |
| `audit.degraded` / `audit.recovered` | 审计写入降级与恢复 |

### 7.2 字段与不可否认性

每条审计事件含：`seq`、`ts`（UTC）、`type`、`actor`（CLI 本地管理员按 socket peer 凭据识别、kernel/agent 按身份）、`object`、`result`、`details`、`prev_event_hash`。

### 7.3 审计不可静默失败

- 审计写入失败 → 高危操作（打点/重置/滚动/导出）**一律拒绝执行**，并记 `audit.degraded`（尽力写入）。
- 采集可继续，但帧标记 `unaudited`；审计恢复后补记 `audit.recovered`，后续帧恢复标记。
- 审计降级状态必须在 `status` 输出中可见，不得静默。

## 八、接入形态与构建

1. **内核模块**：`internal/entropy`（`//go:build entropy`），实现 kernel SPI 并在 `Init` 时注入依赖。
2. **SPI 契约**：新增 `internal/kernel/entropy_interface.go`，声明熵包对内核侧的只读依赖（评分分数与置信区间读取、原始情报读取、拓扑事件订阅）与对外查询接口；kernel 不 import 熵包实现。
3. **装配点**：`cmd/kernel/entropy_on.go` / `entropy_off.go`（off 时 no-op stub，沿用现有 `xx_on/off` 模式）。
4. **构建 tag**：`MODULE_TAGS` 增 `entropy`（`.github/workflows/ci.yml` 与 `scripts/build.sh` 同步）；agent 构建 tags 由 `checks` 扩为 `checks,entropy`。
5. **模块依赖登记**：熵包硬依赖 `integrity`（链头签名）。按 F3 纪律登记到"模块半启用校验"机制：`entropy` 启用而 `integrity` 未启用时，启动即告警（或 fail-fast），不得静默降级为无签名链。
6. **扩展包清单**：`optional/algorithms/packages/entropy-pack/`（`package.json` + `README.md` + `enable.go`/`register.go`），照 `attck-ext-pack` 范式；`.go` 为编译期启用，不支持热插拔。
7. **配置段**：`config.ini` 新增 `[entropy]`（启用、采样节拍、尺度、分箱、阈值、哈希化、保留天数、数据目录），解析与范围校验进入 `internal/config`（保持 config 纯解析、无副作用）。

### 9.2 读取面

- **CLI（方向④ 交付）**：`entropy status`（当前读数 + 状态 + 完整度 + 审计状态）、`entropy show <dim> <scale>`、`entropy history <dim> <scale> --since`、`entropy export`、`entropy verify`；**打点与重置为管理员高危操作，经 CLI 唯一入口**：
  - `entropy baseline set` —— 首次打点或更新基线（记录快照内容哈希与前一基线哈希）；
  - `entropy reset` —— 重置：等价于重新打点，但**强制要求填写重置原因**并单独记 `baseline.reset`（审计语义区分于常规打点）。
- **导出**：JSON/Markdown 离线包（含链与签名信息）。
- **熵事件**：阈值触发事件经 hook 外发，可被扩展包订阅；事件不携带评分写权限。
- **实时推送**（comms 只读方法）列为第二阶段。
- **硬约束**：熵读数不出现在评分报告、评分卡、`AssessmentResult` 及其签名载荷中。

## 十、测试与验证策略

| 类别 | 内容 |
|---|---|
| 算法 | 已知分布的手算向量对照（`Ĥ`/`ΔH`/`KL`）、平滑边界（`p_base=0`）、归一化除数固定性、双读符号约定 |
| 时间 | 多尺度窗口正确性、乱序到达、重复帧幂等、时钟回拨检测、变化率与持续时长 |
| 状态 | 未标定输出 `null`、打点后立即可用、重置语义（读数归零、基线年龄归零） |
| 存储 | 崩溃注入（半帧/半审计记录）、篡改/重排/截断检知、独立密钥域不可互解、umask 0000 下权限保持（RC-L2 范式） |
| 审计 | 事件完整性、交叉锚定、审计失败时高危操作被拒、降级状态可见 |
| 采集 | Linux `/proc` 解析、IP/进程名哈希化、超时与背压、gap 记录、非 Linux stub 编译 |
| 构建 | 单 tag `entropy`、全量 MODULE_TAGS、agent 带 `checks,entropy` 三种组合均通过 |
| 依赖 | 断言熵包依赖闭包**不含** `engine`/`assessor`/`predictor`（`go list -deps` 断言，防评分耦合回归） |
| 端到端 | 启动 → 打点 → 注入行为漂移 → 读数升降 → 链校验 → 重置归零 |
| **非回归** | 开关 `entropy` 对 `AssessmentResult` 逐位无影响 |

## 十一、分阶段实现建议

| 阶段 | 交付 |
|---|---|
| P1 | 算法内核（分布/`Ĥ`/`ΔH`/`KL`/多尺度）+ 单元测试向量（纯函数，无 IO） |
| P2 | 存储层（目录、密钥域、加密帧、哈希链、链头签名、原子写/恢复）+ `internal/integrity` 通用签名扩展 |
| P3 | 审计层（事件表、交叉锚定、降级策略、`verify`） |
| P4 | 采集层（agent 侧四面采样、独立通道、gap、隐私最小化） |
| P5 | 装配与构建（kernel SPI、on/off、MODULE_TAGS、agent tags、扩展包清单、`[entropy]` 配置） |
| P6 | 输出面（结果结构、CLI 熵命令接线、导出包、熵事件 hook） |
| P7 | 端到端与非回归验收（含 `go list -deps` 依赖断言） |

## 十二、未决与第二阶段

- **非对称签名**：如需第三方独立验证，链头改 Ed25519（独立密钥域 + 公钥分发）。
- **实时推送**：comms 新增只读熵接口（需 tag 组合与协议扩展）。
- **方向④ CLI 重构**：运维属性剥离与"高危操作唯一入口"定位由方向④ 完成；本文只约定熵命令与权限语义。
- **方向② 关系**：边缘因子向量图变量化与熵包相互独立；熵包不消费评分权重，方向② 不依赖熵包。
