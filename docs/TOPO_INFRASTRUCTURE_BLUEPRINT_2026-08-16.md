# 拓扑与传播层基础设施蓝图（v0.3.0 特化分支）

**日期**: 2026-08-16 | **版本**: v0.2.3 | **性质**: 基础设施需求统计（不立即实现，为社区接入奠基）
**依据**: `docs/audits/TOPO_MODEL_GAP_SUMMARY_2026-08-16.md`、`TOPO_COMPLEX_AUDIT_T1_T11`、`TOPO_SEMANTIC_AUDIT_T12_T16`、`TOPO_DYNAMICS_AUDIT_T17_T21`

## 一、背景

拓扑与传播层当前实现为**静态、无向、无权重、无生命周期的子网重叠图**（`internal/topology` 的 `map[hostID][]subnet` + SRD 的 subnet-overlap 判定）。21 个实验（T1-T21）证明：传播边在真实网络任何变化下都纹丝不动。

**修复复杂度评估**：非单点缺陷，而是横跨采集、建模、事件、传播、持久化、观测六层的系统性缺口——超出单维护者当前可承担范围。因此**不立即修复**，先统计基础设施需求、定义稳定接口契约、打好地基，等待社区协作。

## 二、基础设施需求清单（按层）

### L1 拓扑数据模型（表示层地基）

| 基础设施 | 需求说明 | 关联缺口 |
|---------|---------|:---:|
| 图结构类型 | `TopologyGraph`：节点（host/network device）+ 边（link）+ 属性（方向/权重/类型/状态） | P0-1/P1-2 |
| 节点模型 | `TopoNode{HostID, Role, Zone, Subnets, Status}`——支持角色/域/状态 | P1-2/P2-2 |
| 边模型 | `TopoEdge{Source, Target, Directed, Weight, LinkType, Status}`——方向/链路类型/质量 | T12/T13 |
| 属性模型 | 链路延迟/带宽/ACL 状态/安全域边界 | T13/T14/T15 |
| 序列化 | 图结构 JSON 序列化（持久化 + 观测 + 调试） | — |

### L2 拓扑事件与生命周期（动态层地基）

| 基础设施 | 需求说明 | 关联缺口 |
|---------|---------|:---:|
| 事件类型 | `TopoEvent{NodeAdded, NodeUpdated, NodeRemoved, LinkUp, LinkDown, LinkAdded, LinkRemoved}` | P0-1 |
| 事件总线接入 | 复用 kernel Bus 发布拓扑事件（现有 TopicAgentHeartbeat 等扩展） | P0-1 |
| 注销机制 | `RecordTopology` 增加 delete/expire；节点超时或心跳丢失时清除/标记边 | P0-1/T17 |
| 链路状态源 | 采集或探测链路 up/down（agent 上报 / kernel 探测） | T18/T19 |
| 事件驱动更新 | SRD 图随事件增量更新（非每次覆盖） | P0-1 |

### L3 采集扩展（输入层地基）

| 基础设施 | 需求说明 | 关联缺口 |
|---------|---------|:---:|
| 网段过滤 | agent/kernel 过滤管理/虚拟网段（RFC1918 白名单或排除表） | P0-2/T4 |
| 字段补全 | `NetworkInfo.Gateways/Neighbors` 采集实现（已有字段未填） | P2-3 |
| 链路属性上报 | 可选：延迟/带宽探测（成本高，先定义接口） | T13 |
| 区域语义 | 可配置 zone 映射（子网→区域），替代硬编码启发式 | P2-2/T15 |

### L4 传播模型（计算层地基）

| 基础设施 | 需求说明 | 关联缺口 |
|---------|---------|:---:|
| 风险加权 | `risk_transmission` 按源风险归一化（failed 检查数/分数/资产价值） | P1-1/T9/T10 |
| 衰减函数 | 传播随跳数/路径衰减（替代固定 0.3） | P1-2/T1 |
| 方向性 | 有向传播（非对称可达性） | T12 |
| 抑制机制 | 低风险源衰减阈值（噪声抑制） | T9 |
| 资产价值元数据 | 关键资产标记 → 权重提升 | T10 |

### L5 可达性与路径（语义层地基）

| 基础设施 | 需求说明 | 关联缺口 |
|---------|---------|:---:|
| 可达性判定 | 替代"子网重叠"：基于真实可达性（路由/ACL 感知） | P1-2/T14 |
| 路径模型 | 跳数/metric/实际转发路径（SRD 边按路径构建） | T1/T2/T16 |
| 安全边界 | ACL/NAT/防火墙状态参与可达性计算 | T14 |

### L6 持久化（状态层地基）

## 三、里程碑拆分（社区可认领）

| 里程碑 | 内容 | 依赖 | 规模估计 |
|:---:|------|:---:|:---:|
| **M0 地基** | L1 图模型类型 + L2 事件类型 + L6 持久化骨架 + L8 注入器 | 无 | 小（可并行） |
| **M1 生命周期** | L2 注销/链路事件 + L3 网段过滤 + L7 拓扑视图 | M0 | 中 |
| **M2 语义** | L5 可达性 + L4 加权/衰减/方向 | M1 | 大 |
| **M3 观测完备** | L7 可视化 + 指标 + 文档 + 基准 | M2 | 中 |

**推荐社区入口**：M0 的 L1/L2/L8 是独立的、无依赖的小型任务，适合 first PR；M1 是 P0 缺口（生命周期 + 网段污染）的直接修复路径。

## 四、地基先行（当前可做，不改传播行为）

1. **接口契约**：在 `internal/kernel` 定义 `TopologyInterface`（Get/Record/Delete/Subscribe 事件），现有 `topology.Registry` 实现之——接口稳定，实现后续替换。
2. **事件类型**：定义 `TopoEvent` 常量与消息结构（Bus topic `topology.*`）。
3. **图模型类型**：`TopoNode`/`TopoEdge` 类型定义（先于实现，供社区基于接口开发）。
4. **测试注入器**：拓扑图注入测试辅助（单元测试即可用）。

> 上述地基四项不改变现有传播行为（子网重叠逻辑保留），只建立稳定接口与类型，供 v0.3.0 特化分支与社区在此基础上演进。

## 五、结论

拓扑层修复是一个 **6 层 × 3 里程碑** 的系统工程。当前策略：**统计基础设施（本文档）→ 打地基（接口/类型/事件/注入器）→ 等待社区**（M0 任务友好化、文档化、里程碑化）。评估与状态层（E 系列验证的可靠内核）继续作为 main 分支的稳定基线。
