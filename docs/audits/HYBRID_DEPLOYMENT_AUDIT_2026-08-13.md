# 轻量内核阵列 + 重型分布式阵列混合筛选 架构审计

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 黑盒阵列部署形态细化（C4 约束的回应）

---

## 一、方案概述

对 C4（性能/体积）约束的落地回应：

| 层 | 部署形态 | 职责 | 模型类型 |
|:---:|------|------|------|
| **轻量黑盒阵列** | 单独编译，跟随内核 | 实时快速召回 | 决策树/规则型/轻量 XGBoost |
| **重型黑盒阵列** | 单独编译，分布式部署 | 深度精确分析 | 深度学习/Transformer |
| **混合筛选** | 两级级联 | 轻量召回 → 重型精确 → 白盒仲裁 | — |

## 二、可行性评估

### 2.1 轻量阵列"跟随内核"的三种落点

| 落点 | 形态 | 内核体积影响 | 通信延迟 | 判定 |
|------|------|:---:|:---:|:---:|
| A. 编译进内核二进制 | build-tag 模块（attck-ext-pack 模式） | 🔴 膨胀内核（几 MB-几十 MB） | 🟢 零（进程内） | ⚠️ 需评估 |
| B. 独立二进制同机部署 | 内核旁路进程，本地 IPC | 🟢 零（内核不膨胀） | 🟡 微秒-毫秒 | ✅ 推荐 |
| C. 内嵌 agent | agent 二进制携带轻量模型 | 🟢 零 | 🟡 随心跳上报 | ✅ 边缘可用 |

**裁定**: 方案 B（独立二进制同机）最优——内核体积零膨胀 + 近零通信延迟 + 可独立升级模型。

### 2.2 重型阵列"分布式部署"的落点

| 形态 | 通信 | 部署复杂度 | 判定 |
|------|------|:---:|:---:|
| 单机 GPU 推理服务 | gRPC/REST | 🟢 低 | ✅ 起步 |
| 多机推理集群 | 负载均衡 + gRPC | 🟡 中 | 规模大时 |
| 云推理 API | HTTPS | 🟡 中 | 需网络 |

### 2.3 混合筛选的级联逻辑

```
轻量阵列(内核同机) ──召回──→ 候选信号 ──→ 重型阵列(分布式) ──精确──→ 高置信候选 ──→ 白盒仲裁
     (毫秒级)                         (秒级)                      (确定性决策)
```

| 级联环节 | 输入 | 输出 | 延迟 |
|------|------|------|:---:|
| 轻量召回 | 原始事件 | 候选信号集 | 毫秒 |
| 重型精确 | 候选信号 | 高置信候选 | 秒级 |
| 白盒仲裁 | 高置信候选 | 确定性动作 | 毫秒 |

## 三、对白盒属性的破坏面积

**仍为零**——只要守住"黑盒不驱动决策"红线：

| 白盒属性 | 破坏面积 | 说明 |
|------|:---:|------|
| SSAM/Prism 评分 | 🟢 零 | 两级阵列均不进入评分 |
| 策略引擎 | 🟢 零 | 阵列输出仍经白盒规则仲裁 |
| 审计可追溯性 | 🟢 零 | 阵列筛选结果作附注 |
| HMAC 一致性 | 🟢 零 | 阵列不参与签名 |

**与前三轮审计结论一致**：本方案是"召回层+精确层"的部署形态细化，未改变"黑盒只召回、白盒决策"的本质。

## 四、性能/体积/部署复杂度评估

### 4.1 体积分布（方案 B）

| 组件 | 体积 | 说明 |
|------|:---:|------|
| 内核二进制 | 不变（~15 MB） | 轻量阵列独立二进制，内核零膨胀 |
| 轻量阵列二进制 | 5-50 MB | 决策树/XGBoost |
| 重型阵列服务 | 100 MB-10 GB | 分布式，独立部署 |
| **总计（单机）** | 内核 + 轻量 | 内核不变 |

### 4.2 性能分布

| 环节 | 延迟 | 资源 |
|------|:---:|------|
| 轻量召回 | 毫秒级 | 同机 CPU |
| 重型精确 | 秒级 | 远程 GPU |
| 白盒仲裁 | 毫秒级 | 内核 CPU |

### 4.3 部署复杂度

| 组件 | 复杂度 | 说明 |
|------|:---:|------|
| 轻量阵列 | 🟢 低 | 同机二进制，随内核启动 |
| 重型阵列 | 🟡 中 | 分布式，需服务发现/负载均衡 |
| 混合筛选编排 | 🟡 中 | 级联逻辑 + 失败回退 |

## 五、新引入的风险

### 5.1 分布式一致性风险

| 风险 | 场景 | 缓解 |
|------|------|------|
| R1 重型阵列不可用 | 分布式服务宕机 | 轻量阵列独立工作，降级为"仅召回" |
| R2 网络抖动 | 召回→精确的级联延迟增大 | 超时 + 本地缓存 |
| R3 轻/重输出不一致 | 轻量召回但重型否决 | 白盒仲裁（重型否决优先） |

### 5.2 级联延迟风险

| 场景 | 影响 | 缓解 |
|------|------|------|
| 重型阵列排队 | 精确分析延迟堆积 | 优先级队列（高置信候选优先） |
| 突发告警洪泛 | 重型阵列过载 | 轻量阵列预过滤 + 采样 |

### 5.3 模型版本一致性

| 风险 | 场景 | 缓解 |
|------|------|------|
| R4 轻/重模型版本漂移 | 轻量阵列升级但重型未升级 | 版本协商 + 兼容性检查 |

| 维度 | 结论 |

| 性能 | ✅ 轻量毫秒级 + 重型秒级，分级合理 |
| 部署复杂度 | 🟡 中（分布式引入新复杂度） |

### 推荐落点

| 组件 | 推荐形态 |
|------|------|
| 轻量阵列 | 方案B：独立二进制同机部署（IPC 通信），内核零膨胀 |
| 重型阵列 | 单机 GPU 推理服务起步，规模大后转集群 |
| 混合筛选 | 级联：轻量召回 → 重型精确 → 白盒仲裁 |
| 降级路径 | 重型阵列不可用时，轻量阵列独立召回（降级但可用） |
