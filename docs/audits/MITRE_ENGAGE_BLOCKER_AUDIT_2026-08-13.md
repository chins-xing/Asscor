# MITRE Engage 作为阻断手段的可行性审计

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: Blocker 接口的主动防御实现评估

---

## 一、核心概念澄清（审计前提）

**MITRE Engage 不是传统"阻断"，而是"主动防御（Active Defense）"。**

| 概念 | 含义 | 与"阻断"的关系 |
|------|------|------|
| 传统阻断 | isolate_host（iptables DROP） | 直接拒绝（deny） |
| MITRE Engage | 蜜罐 + 欺骗 + 引导 | **欺骗性阻断**（deceive + deny + disrupt） |

MITRE Engage 的 8 种方法（Approaches）：

| 方法 | 阻断性 | 说明 |
|------|:---:|------|
| Deny（拒绝） | ✅ 强阻断 | 拒绝攻击者访问真实资产 |
| Disrupt（扰乱） | ✅ 强阻断 | 破坏攻击者工具/进程 |
| Evict（驱逐） | ✅ 强阻断 | 从网络驱逐攻击者 |
| Deceive（欺骗） | ⚠️ 软阻断 | 引导攻击者进入蜜罐 |
| Collect（收集） | ❌ 非阻断 | 收集攻击者情报 |
| Direct（引导） | ⚠️ 软阻断 | 引导攻击者走向死胡同 |
| Detect（检测） | ❌ 非阻断 | 检测攻击者 |
| Assess（评估） | ❌ 非阻断 | 评估攻击者能力 |

## 二、作为 Blocker 接口实现的可行性

### 2.1 接口映射

ASSCOR 已有 `Blocker` 接口（`lifecycle.go`）：

| Blocker 方法 | MITRE Engage 映射 | 实现 |
|------|------|------|
| `Block(ctx, loc)` | Deny + Disrupt + Deceive | 隔离真实资产 + 部署蜜罐 |
| `Unblock(ctx, loc)` | 移除蜜罐 + 恢复 | 拆除欺骗环境 |
| `IsBlocked(ctx, hostID)` | 检查蜜罐/隔离状态 | 查询欺骗部署状态 |

### 2.2 可行性判定

| 维度 | 判定 | 说明 |
|------|:---:|------|
| 接口匹配 | ✅ 完美 | Block/Unblock/IsBlocked 直接对应 |
| 实现复杂度 | 🟡 中 | 蜜罐部署需独立组件 |
| 白盒属性 | 🟡 部分 | 欺骗策略是白盒规则，蜜罐环境可审计 |
| 性能影响 | 🟢 低 | 批处理触发，非流式 |

## 三、与 ATT&CK 推演的协同（核心价值）

**这是 MITRE Engage 的最大亮点——与"攻击链推演"天然契合。**

```
ATT&CK 推演（预测攻击者路径）    MITRE Engage（在预测路径上部署欺骗）
────────────────────────────    ──────────────────────────────
PredictRisk → 推演 T1059→T1021   在 T1021 目标主机部署蜜罐
FindPropagationPaths → 横向移动    在传播路径上布设蜜标
GenerateScenarioFromActor → APT 剧本  按 APT 组织 TTP 定制欺骗

闭环:
攻击者进入蜜罐 → Expose（暴露）→ Collect（情报）→ 反哺 transMatrix
→ 更精准的推演 → 更精准的欺骗部署 → 循环
```

**关键洞察**：传统阻断是"盲阻断"（阻断后失去攻击者视野），MITRE Engage 是"智能阻断"（引导攻击者进入蜜罐，持续收集情报，为下一轮推演提供数据）。

## 四、白盒/黑盒属性评估

| 层级 | 白盒/黑盒 | 说明 |
|------|:---:|------|
| 欺骗策略（何时部署蜜罐） | ✅ 白盒 | 规则驱动，可审计 |
| 蜜罐环境本身 | ✅ 白盒 | 虚假环境可复现 |
| 情报收集 | ✅ 白盒 | 收集的攻击者行为可审计 |
| 攻击者行为分析 | 🟡 可黑盒 | 蜜罐数据的模式识别可黑盒化 |

**结论**：MITRE Engage 的核心（欺骗策略 + 情报收集）是**白盒确定性**的，符合"白盒主路径"红线。黑盒只用于蜜罐数据的模式识别（可选），与黑盒阵列方案一致。

## 五、风险与挑战

| 风险 | 严重度 | 说明 | 缓解 |
|------|:---:|------|------|
| **蜜罐被利用作跳板** | 🔴 高 | 攻击者攻破蜜罐后横向移动 | 蜜罐严格网络隔离（VLAN 隔离） |
| **欺骗暴露** | 🟡 中 | 攻击者识破蜜罐（蜜标探测） | 蜜罐逼真度 + 动态轮换 |
| **法律合规** | 🟡 中 | 主动防御的法律边界（入侵/诱捕） | 合规审查 + 授权范围 |
| **误伤真实用户** | 🟡 中 | 蜜罐误导真实用户 | 蜜罐仅针对已确认攻击者 |
| **部署复杂度** | 🟡 中 | 蜜罐需独立网络环境 | 容器化蜜罐 |

## 七、可行性裁定

**可行，推荐作为 Blocker 的"增强型"实现，而非"替代"传统阻断。**

| 结论 | 说明 |
|------|------|
| 作为 Blocker | ✅ 接口完美匹配 |
| 与推演协同 | ✅ **最强价值**（欺骗部署在预测路径上） |
| 白盒属性 | ✅ 核心白盒（策略+环境+情报可审计） |
| 风险 | 🔴 蜜罐跳板是最大风险，需严格隔离 |
| 定位 | 增强型 Blocker，传统 isolate 保留作兜底 |

### 推荐架构

```
Blocker 接口
  ├─ 传统实现（已有）: isolate_host（iptables DROP）— 兜底，立即阻断
  └─ MITRE Engage 实现（新增）: 蜜罐 + 欺骗 — 增强，智能阻断+情报收集

策略引擎 → 根据攻击者置信度选择:
  高置信攻击者 → MITRE Engage（欺骗+收集情报）
  低置信攻击者 → 传统 isolate（精准阻断）
```

### 推荐落地顺序

1. 🟢 蜜罐容器化（独立 VLAN 隔离，防跳板）
2. 🟢 Blocker 接口的 MITRE Engage 实现
3. 🟡 与 ATT&CK 推演协同（预测路径部署蜜罐）
4. 🟡 情报反哺 transMatrix（蜜罐数据校准转移矩阵）

## 八、结论

**MITRE Engage 作为阻断手段是可行的，且价值远超传统阻断。**

其核心价值不是"阻断"本身，而是**"欺骗增强的阻断"**——在阻断攻击者的同时：
1. **保留攻击者视野**（蜜罐持续收集情报）
2. **反哺攻击链推演**（情报校准 transMatrix）
3. **主动引导攻击者**（走向死胡同，浪费攻击者资源）

与 ATT&CK 推演的协同是最大的亮点：**"预测攻击者路径 → 在路径上部署欺骗 → 攻击者入瓮 → 收集情报 → 更精准预测"** 形成正反馈闭环。

最大风险是**蜜罐被利用作跳板**（攻击者攻破蜜罐后横向移动），必须通过**严格 VLAN 隔离 + 容器化**缓解。同时需注意**主动防御的法律合规边界**。

**定位**：MITRE Engage 应作为 Blocker 的"增强型实现"，与现有传统 isolate_host 并存——高置信攻击者用欺骗（收集情报），低置信用隔离（精准阻断）。全程核心白盒确定性，符合"白盒主路径"红线。
