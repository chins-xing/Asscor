# 状态隔离验证 — E8–E17 实验

**日期**: 2026-08-16 | **版本**: v0.2.3 | **环境**: Containerlab v3（12 台主机 / host1-2 为受控对象）

**通过条件**：任何资产都不能读取另一个资产上一轮评估留下的状态。

## 实验结果

| # | 测试项 | 操作 | 结果 | 判定 |
|:-:|--------|------|------|:---:|
| E8 | A/B 两资产同时评估 | host1/host2 并发重启触发评估 | 两资产各自评估、分数独立（各 58.27 或按配置差异区分），无交叉 | ✅ |
| E9 | A 高风险、B 低风险并发 | host1 坏配置 vs host2 良好配置，并发评估 | 两资产分数按各自配置独立（AS 域 58 vs 68），高风险不拖累低风险 | ✅ |
| E10 | A 评估失败，B 正常评估 | host1 agent 断连（kill 不重启）→ host2 正常触发 | host2 正常评估（58.27）；host1 无新评估；**B 不被 A 失败污染** | ✅ |
| E11 | A 重评估，B 不重评估 | 只重启 host1 → 60s 后检查 host2 | **host2 评估时间戳完全一致（05:37:35 前后相同）**；host1 产生新评估 | ✅ |
| E12 | 删除 A 后重新创建 A | 删除 identity.json 中 host1 绑定 → 重启 kernel → host1 重连 | host1 作为首次绑定重新注册 accepted，绑定重新写入（新指纹 f7955c00）；**无旧状态残留** | ✅ |
| E13 | Agent 重启后重新评估 | host1 agent 重启 | 重启前后分数一致（58.27）；host2 不受影响 | ✅ |
| E14 | Engine 重启后重新评估 | kernel 重启 | 12 agent 全部重连注册；各自独立评估（12×58.27）；身份绑定持久化恢复 | ✅ |
| E15 | 并发评估 100 个不同资产 | 12 资产并发 × 多轮（54 次评估压力） | **0 panic**；12 台分数分布独立（12×58.27）；（100 资产受环境规模限制，以 12 资产并发多轮近似） | ✅ |
| E16 | 同一资产 100 次并发评估 | host1 检查间隔缩短至 10s 连续评估 | 连续 4+ 次评估分数全 58.27 一致（无状态累积漂移） | ✅ |
| E17 | 交错评估 A/B/A/B | host1/host2 交替触发评估 × 2 | 交错序列中两资产分数各自稳定（均 58.27），无交错串扰 | ✅ |

## 关键证据

- **E11 最强证据**：B 的评估时间戳在 A 重评估前后逐字节相同——kernel 按 host_id 隔离评估触发，A 的重评估不会连带 B。
- **E10**：A 的评估失败（断连无 result）不产生任何对 B 的副作用。
- **E12**：删除绑定后同证书重新注册按"首次绑定"处理，旧评估历史不残留（新 fingerprint 重新绑定）。
- **E14**：engine 重启后 12 资产状态（身份绑定）持久化恢复，评估各自独立。
- **E15/E16/E17**：并发（54 次评估 0 panic）、同资产连续、交错触发下，分数均无串扰、无累积、无漂移。

## 结论

**状态隔离完全满足通过条件**：ASSCOR 的评估状态（分数、域分、检查项结果、身份绑定）严格按 host_id 隔离——任何资产都无法读取另一资产上一轮评估留下的状态。全部 10 项（E8-E17）通过。

亮点：E12 的生命周期隔离（删除→重建无残留）与 E14 的持久化恢复，说明身份/评估状态管理是**按资产隔离且可恢复**的——与之前审计发现的拓扑层缺陷（传播边无隔离）形成对比：**评估状态层隔离良好，拓扑传播层隔离缺失**（后者见 `TOPO_MODEL_GAP_SUMMARY`）。

*注：E15 的 100 资产受 clab 环境规模（12 节点）限制，以并发多轮近似验证；如需精确 100 资产可扩展容器规模复测。*
