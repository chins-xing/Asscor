# ASSCOR 复杂网络拓扑专项审计

**日期**: 2026-08-12 | **版本**: v0.2.2 | **范围**: 三大维度

---

## 审计一：内核性能、准确性、可信度与可行性（复杂网络拓扑）

### 总体评级：🔴 C (6个 CRITICAL / 12个 HIGH)

#### 致命缺陷

| # | 问题 | 位置 |
|---|------|------|
| K1 | **无网络拓扑感知** — 全节点视为均匀连接，无子网/VLAN/DMZ/云分区概念 | `assessor.go:1041-1054` |
| K2 | **心跳超时全局统一 60s** — 跨 WAN/卫星链路的 agent 与 LAN agent 使用相同超时 | `heartbeat.go:44` |
| K3 | **CTI 威胁系数全局统一** — 所有 agent 不论区域使用相同威胁乘数，floor 0.60 硬编码 | `cti.go:330-332` |
| K4 | **Goroutine 泄漏** — workerpool 超时后 task goroutine 永久泄漏 | `workerpool.go:97-116` |
| K5 | **事件总线消息静默丢弃** — maxGoroutine 满时丢弃无重试/无死信队列 | `bus.go:119-126` |
| K6 | **SIEM push 无错误返回** — `PushAssessment` 的失败无法被扩展点捕获 | `assessor.go:171-177` |

#### 硬编码阈值一览

| 阈值 | 位置 | 影响 |
|------|------|------|
| 60s 心跳超时 | heartbeat.go:44 | 高延迟链路误报断连 |
| 1h agent 清理 | heartbeat.go:246 | 提前移除跨 WAN agent |
| 0.60 CTI 下限 | cti.go:332 | 最大 40% 降分上限 |
| 10 maxWorkers | engine/assessor.go:156 | 全流程吞吐天花板 |
| 30min 任务超时 | workerpool.go:48 | 挂起任务占用槽位 |
| 256 bus 队列 | bus.go:47 | 突发消息丢失 |
| 1000 断路器窗口 | circuitbreaker.go:20 | 高吞吐场景比例不稳定 |
| 30s 断路器冷却 | circuitbreaker.go:125 | 无指数回退 |

#### 拓扑感知特性清单：零

系统包含**零**拓扑感知特性——无区域发现、无自适应超时、无区域级威胁评分、无差异化的 agent 重要性评估。

## 审计二：SRD 重要 Agent 识别、攻击路径解析、风险扩散准确度

### 总体评级：🔴 D (5个 CRITICAL / 7个 HIGH)

#### 致命缺陷

| # | 问题 | 位置 |
|---|------|------|
| S1 | **无 agent 重要性/关键性排名** — 域控制器与 IoT 传感器同等权重 | `pipeline.go:184-196` |
| S2 | **全连通图拓扑假设** — 所有节点假定彼此连接 | `pipeline.go:186-193` |
| S3 | **硬编码 RiskTransmission=0.1** — 所有边统一传播系数 | `pipeline.go:191` |
| S4 | **虚幻攻击路径** — DFS 在全连通图上枚举数百万条虚假路径 | `paths.go:5-94` × `pipeline.go:184-196` |
| S5 | **RSS 聚合压低单一来源威胁** — 四个相同上游的总风险为 sqrt(4×0.01)=0.2，而非 0.4 | `core.go:21-33` |

#### 数据模型缺失

| 缺失概念 | 现状 |
|------|------|
| Asset 关键性/优先级字段 | 0 节点状态结构体中无此字段 |
| 网络区域（DMZ/内部/云） | 仅 SPC 定义了 4 级暴露模型但从未使用 |
| 横向移动建模（SMB/RDP/PSExec） | 完全缺失 |
| 漏洞链/权限提升建模 | 完全缺失 |
| 时间因果约束 | 全静态快照，无时间线约束 |
| 路径置信度 | 0 不确定性量化 |

#### 硬编码参数

| 参数 | 值 | 来源 |
|------|------|------|
| RiskTransmission | 0.1 | 字面量 |
| PathDecay | 0.80 | config.go:10 |
| MaxPathDepth | 5 | config.go:11 |
| PropCap | 0.25 | config.go:7 |
| ScoreFloor | 0.15 | config.go:12 |

## 审计三：Agent 边缘主机性能消耗与复杂环境连接质量

### 总体评级：🟡 B- (3个 HIGH / 4个 MEDIUM)

#### 关键缺陷

| # | 问题 | 位置 |
|---|------|------|
| A1 | **无 TCP keepalive** — 死连接在下次 RPC 30s 截止前不会被检测到 | client.go 全文件 |
| A2 | **ServerName 硬编码 "localhost"** — 阻止远程内核 mTLS | agent.go:238, 285 |
| A3 | **包列表每心跳完整发送** — 2000 包系统 ~7 MB/h 冗余传输 | agent.go:440 |

#### 中等缺陷

| # | 问题 | 位置 |
|---|------|------|
| A4 | 检查超时 (60s) 硬编码，独立于配置的 `CheckTimeoutSec` (10s) | agent.go:1203 |
| A5 | 无自适应批处理或系统负载感知 — 80 检查最大并发度不变 | agent.go:1176 |
| A6 | 每 RPC 单互斥锁串行 — 无管道化/无多路复用 | client.go:100-101 |
| A7 | 无消息压缩 — 全 JSON 载荷通过 TLS 无 gzip/deflate | 全 agent/client 包 |

#### 性能特征

| 指标 | 数值 | 细节 |
|------|:---:|------|
| 峰值 goroutine | ~160 | 80 检查 × 2 goroutine + 1 |
| 峰值内存 (检查阶段) | ~80 KB | 结果切片 + goroutine 栈 |
| 心跳带宽 (仅元数据) | ~12 KB/h | 每 30s 心跳 |
| 心跳带宽 (含全包列表) | **~7 MB/h** | 每心跳发送全量包名 |
| 重连策略 | 3 次故障后自终止 | 指数回退 30→60→60s |
| TLS 会话复用 | 不配置 | 每次重连完整握手 |

## 总结

| 维度 | 评级 | 致命缺陷 | 高缺陷 |
|------|:---:|:---:|:---:|
| 内核拓扑性能 | **C** | 6 | 12 |
| SRD 风险扩散 | **D** | 5 | 7 |
| Agent 边缘性能 | **B-** | 0 | 3 |
| **合计** | — | **11** | **22** |

### 三个维度的交叉盲点

1. **内核**不知道网络拓扑 → **SRD** 在全连通图上虚幻扩散 → **Agent** 的包数据无法用于拓扑发现
2. 三个层级各自使用独立的硬编码阈值，**无自适应**机制跨层联动
3. **Zone 分类定义在 SPC 中但从未使用** — `assessor.go:793-798` 仅设置 "internal"，使 SPC 的 4 级暴露模型完全失效

### 优先修复建议

| 优先级 | 修复 | 影响 |
|:---:|------|------|
| 1 | `pipeline.go:191` RiskTransmission → Agent 网络区域 × SSAM 得分 × 连接类型 | SRD 扩散准确度 |
| 2 | `assessor.go:1041-1054` 拓扑快照 → 添加 Agent 自报区域 + 子网前缀 + 分组 | 全部三层 |
| 3 | `heartbeat.go:44` 超时 → 基于区域的差异化超时 (LAN 30s/DMZ 60s/WAN 120s) | 减少误报断连 |
| 4 | `agent.go:440` 包列表 → 首次全量发送 + 后续增量差异 | 带宽降至原来的 1% |
| 5 | `workerpool.go:97-116` → 使用 `context.WithTimeout` 取消防止 goroutine 泄漏 | 稳定性 |
| 6 | `client.go` → 添加 TCP keepalive (5min) | 死连接检测 |
