## 四、耦合问题详细分析

### 4.1 架构层面问题

#### 问题 A: 双 Assesor 实现导致职责不清

**当前状态**: 
- `kernel/assessor.go`: 537行，Kernel插件
- `engine/assessor.go`: 1006行，独立引擎

**影响**:
- 代码重复（ACIToAsset函数在两处实现）
- 维护成本加倍
- 接口不清晰

**建议**: 
- 保留 `kernel/assessor.go`（插件体系）
- 将 `engine/assessor.go` 重构为适配器层
- 或合并两者，移除重复

#### 问题 B: 内核层直接导入引擎层

**位置**: [kernel/assessor.go:12](file:///f:\Argus\internal\kernel\assessor.go#L12)
```go
import "github.com/asscor/asscor/internal/engine"
```

**问题**:
- 违反分层架构原则
- 插件层不应依赖具体实现

**建议**:
- 使用接口抽象
- 通过 DI 容器注入依赖

### 4.2 接口层面问题

#### 问题 C: 硬编码类型断言

**位置**: [kernel/assessor.go:54-56](file:///f:\Argus\internal\kernel\assessor.go#L54-L56)
```go
if impl, ok := kc.Container().ResolveNamed("config"); ok {
    if c, ok := impl.(*config.Config); ok {  // 硬编码类型
        m.cfg = c
    }
}
```

**建议**: 使用泛型或接口抽象
