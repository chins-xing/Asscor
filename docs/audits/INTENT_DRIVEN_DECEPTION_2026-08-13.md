# 意图驱动的轻量欺骗精化设计

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 引导式主动防御战略的轻量化精化

---

## 一、战略精化（用户定义）

> 无需使用高逼真蜜凭证。**让攻击者觉得这里有突破口就够了**。识别到意图后，使用轻量蜜罐**主动暴露可疑服务**，或**抛出虚假情报**。

这是对"引导式主动防御"的**轻量化 + 意图驱动**修正。

---

## 二、核心转变

| 维度 | 之前（高逼真导向） | 现在（够用导向） |
|------|------|------|
| 诱饵逼真度 | 高逼真蜜凭证（高成本） | 够用即可（低成本） |
| 部署时机 | 静态部署 | **意图驱动**（识别意图后针对性部署） |
| 暴露方式 | 被动等待攻击者发现 | **主动暴露**可疑服务 |
| 情报投放 | 高逼真蜜文档 | **虚假情报**（蜜标/假数据） |

---

## 三、核心机制：意图驱动的轻量欺骗

```
① 意图识别（Intent Detection）
   └─ ATT&CK 归因 / 技术推断 → 识别攻击者意图
       ├─ 横向移动意图 → 暴露虚假的 SSH/RDP 服务（弱口令诱饵）
       ├─ 凭据窃取意图 → 投放虚假凭据情报
       ├─ 数据窃取意图 → 投放虚假敏感文档
       └─ Web 攻击意图 → 暴露虚假的 Web 服务（有漏洞版本）

② 轻量蜜罐主动暴露（Active Exposure）
   └─ 根据意图，动态启动"看似有漏洞的服务"
       └─ 例如：攻击者在扫 SSH → 主动开一个虚假 SSH 端口（弱口令）

③ 虚假情报投放（Deception Info Drop）
   └─ 抛出蜜标文件 / 假凭据 / 假数据
       └─ 让攻击者"发现"这些情报，暴露其窃取意图

④ 收集（Collect）
   └─ 攻击者触碰诱饵 → 捕获 IP/工具/凭据尝试/行动节奏

⑤ 分析 + 再引导（Assess + Re-guide）
   └─ 收集的情报 → 反哺意图识别 → 更精准的下一轮诱饵
```

---

## 四、"够用原则"的洞察

**攻击者的上钩阈值很低**——不需要高逼真，只需要"看似有突破口"：

| 诱饵类型 | 高逼真成本 | 够用成本 | 效果 |
|------|:---:|:---:|------|
| 蜜凭证 | 逼真域管理员凭据（高） | 普通格式假凭据（低） | 攻击者都会尝试 |
| 蜜服务 | 完整仿真服务（高） | 开放端口 + 简单响应（低） | 攻击者都会探测 |
| 蜜文档 | 逼真加密文档（高） | 看似敏感的文件（低） | 攻击者都会窃取 |

**核心洞察**：攻击者不会深度验证诱饵的真实性，他们看到"疑似突破口"就会尝试利用——这本身就是暴露。欺骗的成本在于"制造突破口假象"，而非"完美仿真实资产"。

## 六、意图 → 诱饵映射（轻量实现）

| 识别的意图 | 轻量诱饵 | 成本 |
|------|------|:---:|
| 横向移动（T1021 远程服务） | 暴露虚假 SSH 端口（22→弱口令） | 极低（TCP listener） |
| 凭据窃取（T1003 凭据转储） | 投放假凭据文件（普通格式） | 极低（文件） |
| 数据窃取（T1041 渗出） | 投放假敏感文档 | 极低（文件） |
| Web 攻击（T1190 漏洞利用） | 暴露虚假 HTTP 服务（有漏洞 banner） | 极低（HTTP listener） |
| 扫描探测（T1046 网络扫描） | 暴露多个可疑端口 | 极低（多端口 listener） |

**全部零重型依赖**：TCP listener + 文件投放，纯 Go 标准库。

## 七、可行性裁定

**可行，且是"引导式主动防御"的最优轻量化落地。**

| 维度 | 结论 |
|------|------|
| 成本 | 🟢 极低（TCP listener + 文件，零重型依赖） |
| 意图驱动 | 🟢 ATT&CK 归因已具备，接线即可 |
| 够用原则 | ✅ 洞察正确——攻击者上钩阈值低 |
| 白盒属性 | ✅ 意图→诱饵映射是确定性规则 |
| 现有基础 | ✅ honeypot/honeytoken/collector 已实现 |

### 与生态轻量化的呼应

本精化完美呼应之前的"生态轻量化"原则——**不追求高逼真（高成本），追求够用（低成本）**。欺骗防御的价值在于"制造突破口假象"，而非"完美仿真"。
