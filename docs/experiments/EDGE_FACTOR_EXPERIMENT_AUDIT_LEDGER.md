## A.3 一致性判据（**可复跑**）

判据的**输入**是一份**双侧登记**的有意差异清单：

```text
<登记 blob sha(ARC 侧 HEAD)>  <登记 blob sha(main 侧 BASE_REF) | ABSENT>  <路径>  # 理由
```

- 两侧都有的文件记 **main 侧** blob sha；只在 ARC 有的文件记字面量 **`ABSENT`**；
- **任一侧与登记不符都报红**（`ABSENT` 变成"确实存在"也算不符）
  ⇒ 这样"**main 侧被改写**"这种旧版发现不了的形态也能被抓住；
- 已用**变异测试**验证：改写 `internal/model/model.go` 的 main 侧 +
  让 `internal/model/edgefactor_chain_test.go` 在 main 上凭空出现 ⇒ **两处都被判红**。

| 输出 | 含义 | 处置 |
|---|---|---|
| **绿 exit=0** | 底座路径两侧**逐字节相同**（清单为空或全部已同步） | 可以继续 |
| **黄 exit=3** | 清单外逐字节一致；清单内有意差异**两侧均与登记一致** | **裁定「乙」的合格终态** |
| **红 exit=1** | ①清单**之外**出现漂移 ②ARC 侧与登记不符 ③**main 侧与登记不符** ④清单行缺 main 侧登记 | 要么**消除**漂移（按规则②上 main），要么**登记**（按规则④写理由与引入提交） |

## B.1 `L2`：客观标签的语义（用户 2026-09-12 裁定，**实验执行前必须遵守**）

| 项 | 内容 |
|---|---|
| **裁定** | 客观标签 `compromised` 定义为"**该场景的*目标 TTP* 是否成功**"，**不是**"主机是否被攻陷"；记录与论文**必须**逐条写明这一语义 |
| **依据（实测）** | 在一台**六个控制全在**的硬化容器上跑固定剧本 `Discovery`：`links=14`、`status={0:13, -3:1}` ⇒ `successes=13` ⇒ `compromised=true`、`block_effective=false`。`Discovery` 全是**只读侦察**能力（列用户、看进程），**任何**本实验的控制集都不会阻止它 ⇒ 用"是否被攻陷"作标签在真实环境里**恒为真、零方差**，决策层指标**不可算** |
| **目标 TTP 的选择** | 只做"**AppArmor 自定义限制策略 + 撞策略的 TTP**"一侧：在目标容器上加一条**真实**的限制性策略，用一条会撞它的 ability ⇒ 策略加载 ⇒ 被拒（`compromised=false`）、策略卸载 ⇒ 成功（`compromised=true`）。**禁止**用"只改标签"制造方差 |
| **可算范围** | 决策层指标（漏判率/误阻断率/AUC）**只对带目标 TTP 的记录可算**；其余因子场景**只作分数侧**，其标签**不得**用固定侦察剧本的恒真结果顶替（用 `ground_truth.basis` 区分） |
| **分数侧的诚实口径** | 容器内 `aa-status` 恒报 profiles loaded ⇒ `OT-005` 在真机上**不会**翻成失败，场景"该防护缺失"仍按既有机制**合成注入**；报告/论文**不得**写成"真机上该检查真的失败了" |

### B.3.1 「链上同一因子出现两次」的判词与产物规则（Task 18，2026-10-16）

> 这条**从属于 B.3**：它同样是"观测到的东西 ≠ 建模该用的东西"这一类口径问题的产物。

| 项 | 内容 |
|---|---|
| **现象** | 门禁⓪ 报：链上**每个出现过的因子恰好 2 条**（CT 与 VM 同形态，**与基质无关**） |
| **根因（实测，探针逐条打印）** | **不是"同一条目写两次"**，而是配置**真的声明了两个同名条目**：`[edge_factors]`（内置 7 条，**大写 ID**）+ `[edge_factors.custom]`（另 7 条，解析层**已小写**）⇒ `ConfigToEdgeFactors` 得 **14 条、刻意不去重**（P4）；而 `ssam-lib` 的 `ApplyEdgeFactorsToChecksPolicy` 用 `efMap[f.ID]` **按原始大小写建键**、末尾 `sort.Slice(by ID)` ⇒ **ASCII 序把两块字典序拼在一起**；`NormalizeFactorID` 再把两条压成同名 ⇒ 链上"每个因子两条" |
| **判词** | **真缺陷（有害），但只在 V/G/C 路径** —— 模型层的参数空间是**因子级**（`Factors`/`Vectors`/`Coupling` 全按归一 ID 建键），而喂进去的是**条目级的多重集** |
| **定量后果（实测，非推断）** | 主效应 `Σ a_i` **恰好 ×2**（`L[AS]` 0.162 vs 0.081）；耦合项 `Σ c_ij a_i a_j` **恰好 ×4**（实测 0.001134 = 4 × 0.0002835）。**2:4 的比例畸变 λ 吸收不掉**，而这正是 G/C 要估计的对象。且 `n_i` **逐记录不同**（33 条里 3 条 `n_i=1`）⇒ **跨场景 `L` 不可比** |
| **内部矛盾（第三条判据）** | `fit.go:design()` 用 `eff[FactorID]=…` 建 map ⇒ **未文档化的 last-wins 静默折叠**（真机取到 custom 的 0.85），而 `Synthesize` 不折叠 ⇒ **同一份记录在拟合侧与评分侧口径不同** |
| **产物规则（唯一实现）** | `internal/edgefactor/collapse.go` 的 **`CollapseToFactors`**：**每个规范因子 ID 留一项、取最强观测惩罚**（`EffectiveFactor` 最小）、并列取先出现者、输出按 ID 升序。3 个调用点：`internal/engine/ssam/activationsFromResults`、`cmd/edgecompare/{activationsFromResults,activationsOf}` |
| **不取的口径（如实登记）** | 备选 **"净乘子 ∏ 条目 eff"** **不取**：它会把 **24/33 条无争议记录**的 `a_i` 由 `1−f` 改成 `1−f²`，且是**设计文档里没有的第三种语义** |
| **边界（不夸大）** | **链、配置、`ConfigToEdgeFactors`、legacy 评分一律不动** —— **链上的重复对 legacy 是载荷**（P4；首次红输出当场证明：`S1-apparmor-01` 57.91 → 折叠后 62.05），且**门禁⓪ 正是要观测它**。`Synthesize` **一行未动**（不在求和处打补丁） |
| **要不要重跑批次** | **不用**（已独立复核）：门禁② 33 条 `max_abs_delta=0`、legacy 列逐位不变、真机 m0 记录逐字段相同、**门禁① 聚合表在起点与 HEAD 上逐字相同**（含"未选模"）。只有 V/G/C 逐条数值上升 `+0.04…+1.15`（重算 = 分钟级） |
| **论文措辞禁令（第三条）** | **"每个因子恰好出现两次"只是这批矩阵的观测、不是不变量**（33 条里 3 条 `n_i=1`）—— 不许写成不变量 |
| **残留裁定项** | 冲突条目（0.70/0.85）取"最强惩罚"是本次选择；若改判"净乘子"，改动只有 `collapse.go` 的一处比较与两条测试期望值。**在裁定落地前，论文引用 V/G/C 分数（尤其拟合出的 `c_ij`）须标注"折叠规则 = 最强观测惩罚"** |

## C.1 基质分工原则（**用户 2026-10-15 裁定**）

> **原话要点**：「**CT 的作用本来就是快速验证和轻量模拟，应该作为临时短期任务的选择。
