# ARGUS 1.2 工程实现白皮书

**版本：** 1.0  
**日期：** 2026-05-12  
**状态：** 草案  
**配套理论文档：** ARGUS 1.2 项目白皮书（第一篇章）、等级保护检查项映射手册（第二篇章）、监管委员会章程（第三篇章）

## 摘要

本文是 ARGUS 1.2 安全可接受性模型的工程实现规范，详细描述分布式评估系统的技术选型、架构设计、模块划分、通信协议、数据模型、安全机制、构建部署与扩展策略。系统采用 Go 语言实现的微内核 + Agent 架构，通过 gRPC 与 mTLS 实现高性能、安全的双向通信。所有设计遵循低耦合、可扩展、零外部依赖（核心）原则，方便社区贡献与跨平台部署。

## 1. 技术选型

| 层次 | 选用技术 | 选择理由 |
|------|----------|----------|
| 编程语言 | Go 1.21+ | 静态编译，零依赖分发，原生并发，跨平台支持 |
| 通信协议 | gRPC + Protocol Buffers | 强类型接口定义，高性能二进制序列化，双向流，内置负载均衡与超时 |
| 传输安全 | mTLS (双向认证) | 确保内核与 Agent 间身份认证与加密，防止中间人攻击 |
| 配置格式 | INI (通过自定义解析器) | 简单易读，管理员可直接编辑，无需特殊工具 |
| 并发控制 | Goroutine + Channel + Semaphore | 利用 Go 原生并发实现检查项并行执行，信号量限制并发数 |
| 数据存储 | 内存缓存 + 可选持久化 (SQLite/PostgreSQL) | 评估结果实时计算，缓存5分钟；历史数据按需扩展 |
| 前端仪表板 | 待定 (建议 React/Vue + Go API 网关) | 初期提供 CLI 输出与 JSON 报告，Web UI 作为社区贡献模块 |
| 容器化 | Docker + Kubernetes (可选) | 内核可容器化部署，Agent 推荐直接运行于宿主机 |

## 2. 总体架构

系统采用微内核 + Agent 分布式架构，内核作为中央安全大脑，Agent 作为分布在各业务主机的执行探头。

### 2.1 内核节点 (单实例或多实例联邦)

```
内核节点 (单实例或多实例联邦)
│
├── gRPC Server (监听 0.0.0.0:50051)
│   ├── KernelService   (Agent 注册、心跳)
│   └── AgentService    (拉取快照、下发命令、日志流)
│
├── 内部组件 (通过消息总线通信)
│   ├── 评估引擎 (Assessor)
│   ├── 策略管理器 (Policy Manager)
│   ├── 安全态势计算器 (SPC)
│   ├── 威胁情报管理器 (CTI Manager)
│   ├── 指令下发器 (Commander)
│   ├── 日志收集器 (Log Collector)
│   └── 心跳监控器 (Heartbeat Monitor)
│
└── 数据存储
    ├── 主机资产清单 (内存 + 可选持久化)
    ├── 评估结果缓存 (带 TTL)
    └── 审计日志 (只追加文件/远程 syslog)
```

### 2.2 Agent (每台业务主机)

```
Agent (每台业务主机)
├── gRPC Client (mTLS 连接内核)
├── 状态采集器 (执行本地检查项)
├── 指令执行器 (调用系统命令/API)
└── 文件监控 (可选)
```

## 3. 模块详细设计

### 3.1 内核模块

#### 3.1.1 评估引擎

- **职责**：加载检查项，并发执行评估，计算核心域得分，应用边缘因子、威胁系数、SPC 修正，生成最终 ARGUS 分数。
- **关键接口**：Evaluate(hostID) -> AssessmentResult
- **并发模型**：使用 Goroutine 池，最大并发 10，通过 channel 信号量控制。
- **缓存**：结果缓存 5 分钟，由读写锁保护。

#### 3.1.2 策略管理器

- **职责**：读取配置阈值，根据分数区间生成自动化动作。
- **状态机**：OK (≥阈值) -> Warning (阈值-10) -> Critical (阈值-30) -> Isolated (<阈值-30)
- **动作映射**：notify_admin, increase_assessment, block_ip, disable_service, isolate_host。

#### 3.1.3 安全态势计算器 (SPC)

- **职责**：从 NVD、EPSS、CISA KEV 拉取漏洞情报，与本地资产清单比对，输出 $P_{score}$、$P_{weight}$、$P_{action}$。
- **数据源**：REST API 或本地镜像，定期更新（1h）。
- **本地化因子**：MatchType, ExposureLevel, ControlFactor。

#### 3.1.4 威胁情报管理器

- **职责**：接入 OTX、MISP 等情报源，计算全局威胁系数 μ。
- **接口**：GetThreatCoefficient() -> float64

#### 3.1.5 指令下发器

- **职责**：将策略管理器生成的动作转化为 Agent 可执行的命令，通过 gRPC 下发，管理重试与超时。
- **签名**：HMAC-SHA256 对命令签名，Agent 验证。

#### 3.1.6 日志收集器

- **职责**：接收 Agent 推送的日志流，写入本地或远程日志存储。
- **存储**：仅追加文件，或转发至 SIEM。

#### 3.1.7 心跳监控器

- **职责**：跟踪每个 Agent 的最后心跳时间，超时 (默认 60s) 触发失联告警。

### 3.2 Agent 模块

#### 3.2.1 状态采集器

- **职责**：执行 ARGUS 定义的检查项，生成 CheckResult 列表。
- **检查项实现**：基于 Go 系统调用、文件读取、命令执行。例如：
  - AS-001 检测不必要的服务：解析 systemd 或 /etc/init.d
  - OT-001 文件权限：os.Stat 获取文件 mode
  - RS-005 SYN Cookie：读取 /proc/sys/net/ipv4/tcp_syncookies
- **扩展性**：允许加载外部 Lua 脚本或 WebAssembly 插件（未来）。

#### 3.2.2 指令执行器

- **职责**：接收内核命令，映射到本地操作（如调用 iptables、systemctl、ufw）。
- **安全限制**：白名单命令集，禁止执行任意 shell 脚本。

#### 3.2.3 安全通信代理

- **职责**：管理 gRPC 连接、mTLS 证书、心跳定时器、日志流上传。
- **证书管理**：首次启动生成 CSR，管理员在内核批准后签发证书。后续自动轮换。

## 4. 通信协议与接口定义

### 4.1 Protobuf 服务定义

```protobuf
syntax = "proto3";
package argus;

service KernelService {
  rpc Register(RegisterRequest) returns (RegisterResponse);
  rpc Heartbeat(HeartbeatRequest) returns (HeartbeatResponse);
}

service AgentService {
  rpc GetSnapshot(SnapshotRequest) returns (SnapshotResponse);
  rpc ExecuteCommand(CommandRequest) returns (CommandResponse);
  rpc StreamLogs(stream LogEntry) returns (Ack);
}

message RegisterRequest {
  string host_id = 1;
  string hostname = 2;
  string version = 3;
}

message RegisterResponse {
  bool accepted = 1;
  string session_id = 2;
  string ca_certificate = 3; // 用于 Agent 验证内核
}

message HeartbeatRequest {
  string host_id = 1;
  string session_id = 2;
  AssessmentResult result = 3; // 嵌入式评估结果，减少 RPC 次数
}

message HeartbeatResponse {
  bool ok = 1;
  double threat_coefficient = 2;
  repeated Command pending_commands = 3;
}

message AssessmentResult {
  double final_score = 1;
  bool acceptable = 2;
  map<string, double> domain_scores = 3; // 核心域得分
  repeated CheckResult checks = 4;
}

message CheckResult {
  string check_id = 1;
  string domain = 2;
  bool passed = 3;
  double delta = 4;
  string detail = 5;
}

message Command {
  string command_id = 1;
  string command = 2;            // 如 "block_ip"
  map<string, string> params = 3;
  string signature = 4;          // HMAC 签名
}

message CommandResponse {
  string command_id = 1;
  bool success = 2;
  string output = 3;
}
```

### 4.2 安全通信流程

1. Agent 启动，生成密钥对和 CSR。
2. 调用 Register，内核验证主机 ID 是否白名单（或管理员审批）。
3. 内核签发 Agent 证书，返回 CA 证书。
4. Agent 与内核建立 mTLS 连接，后续 RPC 均在此连接上进行。
5. Agent 定期（如 5s）发送 Heartbeat，携带最新评估快照。内核返回待执行命令列表。
6. 内核调用 ExecuteCommand 下发指令，Agent 执行后返回结果。
7. Agent 可选调用 StreamLogs 推送实时日志。

## 6. 并发与性能设计

- **评估并发**：检查项执行使用 errgroup 或手动 Goroutine 池，限制并发 10，避免资源耗尽。
- **心跳批处理**：Agent 在心跳中打包评估结果，减少 RPC 次数。内核异步处理心跳，采用 sync.Map 存储主机状态。
- **SPC 计算**：定时任务（1h）在后台 Goroutine 运行，结果缓存，评估时直接读取。
- **日志流**：Agent 端使用异步缓冲 Channel，批量发送，失败重试。

## 7. 安全实现

- **mTLS 证书**：使用 Go 的 crypto/tls，内核加载 CA 证书与服务器私钥，Agent 加载客户端证书。证书生成可用内置 CA（基于 crypto/x509）。
- **指令签名**：内核使用 hmac.New 对命令体签名，Agent 验签。
- **Agent 权限**：Agent 以非 root 用户运行，通过 sudo 规则仅允许执行必要的网络/服务管理命令。
- **内核加固**：内核自身运行 ARGUS 自评估，得分低于 90 发出告警；监听端口仅对 Agent 网段开放。

## 8. 构建与部署

### 8.1 编译

```bash
# 内核
go build -o argus-kernel ./cmd/kernel

# Agent
go build -o argus-agent ./cmd/agent

# 交叉编译 Windows Agent
GOOS=windows GOARCH=amd64 go build -o argus-agent.exe ./cmd/agent
```

### 8.2 运行

```bash
# 内核 (默认读取 config.ini)
./argus-kernel -config config.ini -listen :50051

# Agent
./argus-agent -kernel 192.168.1.100:50051 -host-id web-server-01
```

### 8.3 容器化

```dockerfile
FROM golang:1.21 as builder
WORKDIR /app
COPY . .
RUN go build -o argus-kernel ./cmd/kernel

FROM debian:bookworm-slim
COPY --from=builder /app/argus-kernel /usr/local/bin/
COPY config.ini /etc/argus/
CMD ["/usr/local/bin/argus-kernel", "-config", "/etc/argus/config.ini"]
```

> **注意**：Agent 不推荐容器化，因需要访问宿主机系统状态。

## 9. 扩展性设计

- **自定义检查项**：通过配置文件执行外部脚本（command 字段）注入；未来支持 Lua/WebAssembly 沙箱。
- **攻击向量插件 (AVD)**：在 attackvectors/ 目录中注册新检测逻辑，框架自动加载。
- **多内核联邦**：内核提供 gRPC 服务供上层联邦层调用，交换集群评估结果。
- **IDS 集成**：定义 IDSConnector 接口，可实现 Suricata/Snort 告警接入。

## 10. 从现有 Python DSC 模块迁移

现有 Python 模块（firewall_controller、service_controller 等）逻辑直接迁移为 Go 的检查函数。例如：

```go
// checks/linux/firewall.go
func CheckFirewallStatus() (bool, string) {
    // 执行 iptables -L 或检查 firewalld 状态
    // 返回是否活动及详情
}
```

这样 Python 原型可作为 Agent 的早期参考实现，Go 版本作为正式产品。
