# 引导式主动防御战略审计与设计

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 全自动链路核心战略转向

---

## 一、战略核心（用户定义）

> 链路核心要以**引导**的方式尽可能收集攻击者信息，制造**信息不对等**。通过 MITRE Engage 的能力持续**引导并引诱**攻击者，迫使其**放弃慢速潜伏、转为快速验证**，从而暴露更多信息，来**构建下一次引导**。

这是一个**情报驱动的主动防御正反馈闭环**，与之前"阻断导向"的链路有本质区别。

---

## 二、战略要素拆解

| 要素 | 含义 | 传统阻断 vs 引导 |
|------|------|------|
| **信息不对等** | 防御方部署攻击者不知的虚假环境，获得单向观察优势 | 阻断=切断信息流；引导=持续观察 |
| **引导引诱** | 用高价值诱饵引导攻击者行动 | 阻断=拒之门外；引导=请君入瓮 |
| **迫使快速验证** | 慢速潜伏难检测 → 设计诱饵迫使其行动 | 阻断=攻击者知被察觉；引导=攻击者以为成功 |
| **构建下一次引导** | 收集的 TTP/工具/意图反哺下一轮引导 | 阻断=一次性的；引导=迭代升级 |

---

## 三、与现有全自动链路的映射

### 3.1 当前链路（阻断导向）

```
探测 → 定位 → 响应 → 报告 → 阻断(isolate_host) → 修复 → 验证 → 定位 → 归档 → 重复
                                      ↑
                              核心在"阻断"
```

### 3.2 目标链路（引导导向）

```
探测 → 定位 → 引导(Deceive) → 收集(Collect) → 分析(Assess) → 决策 → 再引导/阻断
                                                                    │
                                      ┌─────────────────────────────┘
                                      │ 攻击者持续活跃 → 升级引导
                                      │ 引导无效/确认真实威胁 → 阻断(最后兜底)
                                      ▼
                             归档（情报积累 → 下一次引导）
```

**关键转变**：`Block` 阶段从"立即 isolate_host"变为"先引导收集，阻断仅作兜底"。

```
│                    引导式主动防御闭环                    │

│                                                          │
│  ④ 决策(Decide)                                          │

│     └─ 引导无效/确认真实威胁 → 阻断(isolate_host 兜底)   │
│                                                          │
│  ⑤ 归档(Archive)                                         │
│     └─ 情报积累 → ① 下一次更精准的引导                   │

```

## 六、需要新增的能力

### 6.1 Guide 阶段（替代 Block 的默认行为）

```go
// LifecycleEngine 新增 Guide 阶段（在 Block 之前）
// Guide: 部署蜜罐/蜜标（引导），而非立即阻断
type Guider interface {
    Guide(ctx, loc *AttackerLocation) (*GuideResult, error)
    // 返回部署的诱饵 + 捕获的情报
}
```

### 6.2 正反馈循环

```go
// 引导循环：持续引导 → 收集 → 分析 → 升级引导
// 阻断仅当：引导无效（攻击者未触碰诱饵）或确认高危
```

### 6.3 情报驱动的诱饵升级

```
第1轮引导：通用蜜罐（端口诱饵）
第2轮引导：针对性蜜标（根据第1轮收集的 TTP 定制）
第3轮引导：高逼真蜜凭证（根据攻击者尝试的凭据格式定制）
```

## 七、信息不对等的技术实现

| 不对等维度 | 实现 |
|------|------|
| **攻击者不知自己在虚假环境** | 蜜罐/蜜标足够逼真，与真实资产混同 |
| **防御方单向观察** | 蜜罐命中 → 捕获 IP/工具/凭据/时间线 |
| **防御方掌握攻击者 TTP** | 捕获的行为 → 反哺 ATT&CK 归因 + transMatrix |
| **攻击者不知已暴露** | 不阻断，攻击者以为成功，持续暴露 |

---

## 八、迫使快速验证的技术实现

| 诱饵设计 | 效果 |
|------|------|
| 高价值蜜凭证（看似域管理员凭据） | 引诱攻击者立即尝试登录（快速验证） |
| 看似重要的蜜文档（看似加密/敏感数据） | 引诱攻击者立即窃取 |
| 看似存在的横向移动目标 | 引诱攻击者立即横向移动 |

攻击者一旦"快速验证"，就暴露了：使用的工具、尝试的凭据、目标偏好、行动节奏。

## 九、对现有实现的调整

| 现有 | 调整 |
|------|------|
| `LifecycleEngine` 的 Block 阶段默认 isolate | Block 阶段改为 Guide 阶段（部署诱饵） |
| `KernelBlocker`（isolate_host 立即执行） | 降级为兜底（Guide 无效时才调用） |
| `EngageBlocker`（MITRE Engage 扩展包） | 升级为 `Guider`（引导 + 收集 + 再引导） |
| `Collector`（质量过滤） | 增强：情报驱动的诱饵升级 |

## 十、可行性裁定

**可行，且是 MITRE Engage 理念的完整落地。**

| 维度 | 结论 |
|------|------|
| 战略正确性 | ✅ 情报驱动主动防御是成熟理念（MITRE Engage/Cyber Deception） |
| 现有基础 | ✅ 蜜罐/蜜标/Collector 已实现 |
| 核心转变 | 需重构 LifecycleEngine 的 Block→Guide |
| 白盒属性 | ✅ 引导策略可确定性规则化 |
| 风险 | 🔴 蜜罐被利用作跳板（需 VLAN 隔离，已审计） |

### 关键洞察

之前审计的"MITRE Engage 作为阻断手段"实际上**误读了 MITRE Engage 的本质**——它不是阻断工具，而是**引导工具**。用户现在的战略澄清了这一点：

- **MITRE Engage 的核心 = 引导（Deceive）+ 收集（Collect）+ 诱敌深入（Elicit）**
- **阻断（isolate_host）= 最后兜底，非核心**

这颠覆了之前"Block 阶段默认 isolate"的设计，核心应从"阻断"转为"引导"。
