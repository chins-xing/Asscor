# AI 黑盒模型自身安全性审计 — 新兴攻击面

**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 黑盒阵列方案的最深层风险——AI 模型本身是否安全

---

## 一、核心结论

**用户点破了此前五轮审计的一个隐含假设。**

前五轮审计建立的"黑盒不驱动决策"红线，隐含假设了：**黑盒输出虽不可审计，但至少是"善意"的（在尽力正确识别攻击）**。

本轮揭示：**黑盒可能被攻击者操控，输出是"恶意"的**。AI 模型本身是新兴且极不成熟的攻击面，防御手段几乎全部处于研究阶段。

**这是"黑盒召回"方案的最危险攻击面，且无成熟防御。**

## 三、对 ASSCOR 白盒架构的具体威胁路径

### 3.1 两层威胁模型

```
第1层（前五轮已覆盖）：黑盒输出"不准确"（误报/漏报）
    → 白盒仲裁兜底 ✅

第2层（本轮揭示）：黑盒输出"恶意"（被攻击者操控）
    → 白盒仲裁可能被误导 🔴
```

### 3.2 恶意黑盒的三种攻击路径

| 攻击 | 机制 | 对白盒的后果 |
|------|------|------|
| **投毒绕过检测** | 攻击者行为被训练进"正常"类 | 白盒收到"无威胁"信号 → 漏报 |
| **对抗性样本** | 构造让模型判"安全"的输入 | 真实攻击被筛掉 → 白盒兜底也漏 |
| **误报洪泛** | 攻击者让模型把正常行为标"攻击" | 白盒被噪声淹没 → 漏判真实攻击 |

### 3.3 白盒仲裁的脆弱性

此前认为"白盒仲裁兜底"能抵消黑盒误报。但**恶意黑盒**可以：
1. 系统性漏报（让白盒以为一切安全）
2. 定向误报（让白盒把资源浪费在假告警上）

白盒的"确定性仲裁"在面对**被操控的输入**时，无法区分"黑盒误判"和"黑盒被攻破"。

## 四、"零信任黑盒"——红线需要升级

### 4.1 前五轮红线

> 黑盒输出不直接驱动决策，白盒仲裁兜底。

**隐含假设**：黑盒输出是"善意参考"。

### 4.2 升级后的红线

> **黑盒输出视为不可信输入，与攻击载荷同等对待。**

即：黑盒输出（召回信号）本身必须经过与"攻击检测"同样严格的白盒验证，因为黑盒信号本身可能被投毒。

---

## 五、新兴领域的不确定性

### 5.1 防御手段成熟度评估

| 防御 | 成熟度 | 可行性 |
|------|:---:|:---:|
| 对抗训练 | 研究阶段 | 🟡 部分有效，可被更强的对抗样本绕过 |
| 模型验证/证书 | 研究早期 | 🔴 无成熟标准 |
| 可解释性审计 | 研究阶段 | 🟡 局部可解释，无法全局验证 |
| 权重签名 | 工程可行 | 🟢 可防供应链篡改，防不了逻辑后门 |
| 运行时监控 | 工程可行 | 🟡 只能检测异常，无法防定向攻击 |

### 5.2 核心不确定性

**AI 安全领域尚无可证明的安全保证**。与传统白盒安全（加密算法可数学证明）不同，神经网络的安全性无法形式化验证。这意味着：

- 任何黑盒模型，无论训练多好，都可能存在未知的对抗性漏洞
- 防御手段（对抗训练等）是"猫鼠游戏"，无终局

## 六、可行性裁定

### 6.1 对黑盒阵列方案的重新评估

| 维度 | 前五轮结论 | 本轮修正 |
|------|------|------|
| 破坏白盒属性 | 🟢 零 | 🟢 零（架构上仍可隔离） |
| 黑盒自身安全性 | 未考虑 | 🔴 **无保证** |
| 白盒兜底有效性 | 充分 | 🔴 **可能被恶意黑盒绕过** |

### 6.2 结论

**黑盒召回方案的架构隔离是正确的，但"黑盒自身安全性"是一个无法在当前技术条件下解决的问题。**

这不是 ASSCOR 的设计缺陷，而是整个 AI 安全领域的**未解难题**。任何引入黑盒模型的安全系统都面临同样的问题。

### 6.3 务实建议

| 策略 | 说明 |
|------|------|
| **最小化黑盒依赖** | 黑盒只做"辅助召回"，白盒独立探测通道是主路径 |
| **黑盒输出白盒验证** | 黑盒召回的每个信号，白盒用确定性规则复核 |
| **权重签名 + 供应链审计** | 防篡改（可做，防不了逻辑后门） |
| **可解释模型优先** | 决策树/规则型可人工审计，深度模型仅作实验 |
| **黑盒降级可关闭** | 黑盒异常时能一键降级为纯白盒模式 |

---

## 七、最终裁定

**AI 黑盒模型是 ASSCOR 混合架构中最危险的攻击面，且属于新兴未成熟领域，无成熟防御。**

此前五轮审计的"黑盒不驱动决策"红线是**必要但不充分**的——它解决了"架构隔离"，但没解决"黑盒被攻破后白盒是否仍可靠"。

**核心洞察**：引入黑盒的本质是引入一个"不可形式化验证的信任边界"。无论架构隔离做得多好，只要黑盒输出被白盒信任（哪怕是间接的召回信号），就存在被对抗性攻击/投毒突破的风险。

**务实结论**：
1. 黑盒阵列**不应成为主路径**，只能作"辅助召回"，白盒独立探测通道必须保持为**主路径 + 兜底**
2. 黑盒输出必须经受与攻击检测同样严格的白盒复核
3. 保留"纯白盒模式"作为黑盒异常时的降级兜底
4. 承认 AI 安全是未解难题，不把安全保证建立在黑盒的可信性上
