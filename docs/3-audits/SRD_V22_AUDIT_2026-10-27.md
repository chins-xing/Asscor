# SRD v2.2 审计报告（2026-10-27）

> 审计对象：SRD **v2.2 / v2.2.1**（`internal/version.SRDVersion = "2.2.1"`）。
> 方法：代码逐条对照 + 运行时复现（VM 910）。**结论按证据分级，不按 changelog 措辞。**

## 0. 一句话结论

**语义层（L1–L5、会话语义、接口级 ACL、角色/区域）已实现且有单测；
但 v2.2.1 声称的"参数可调"在运行时并未生效** —— `[srd]` 配置写进 kernel.ini 后，
启动日志仍显示默认值。数据落库链路（agent → comms → topology registry）**已验证可用**。

## 3. P0 根因分析（A-1）

`Manager.Init` 中：

```go
if cfgObj := kc.GetConfigObj(); cfgObj != nil {
    m.loadConfig(cfgObj)
}
```

运行时 `SRD effective config` 为默认值，说明二选一：

1. `Init` 执行时 `kc.GetConfigObj()` 为 nil（配置尚未注入）——**最可能**；
2. 注入的配置对象不含 `[srd]` 键（已被 v2.2.1 的 `adapterSections` 白名单修复排除，
   且单测 `TestGetExposesSectionKeys` 证明 Parse 后键存在）。

**验证方法（下一步）**：在 `Manager.Init` 里对 `cfgObj` 打一条 info 日志
（类型 + `srd.layered_graph` 读值），重启看是 nil 还是空串——一次即可定因。

## 4. 修复计划（按优先级）

1. **A-1（P0）**：定位 Init 时序；若配置后置，则由 kernel 在配置就绪后调用
   `srd.Manager.ApplyConfig(*config.Config)`（新增导出方法），或在 `Start` 时再读一次。
   验收：kernel.ini 写 `layered_graph=false / transmission=0.42 / max_path_depth=7`，
   重启后日志必须逐项一致；改回默认再验一次。
2. **A-2**：更正 changelog 的"可调"表述为"已接线，启动生效待修（A-1）"。
3. **A-6**：用 v2.2 语义重跑 10 轮随机 ACL 的 ROC，更新 `SRD_CHANGELOG` 里的量化依据。
4. **A-7**：核对 `inferZone` 对私网/管理网的判定，必要时改为可配置区域表。
5. **A-4/A-5**：补非对称 INPUT 场景与 `ct state` 顺序的解析用例；不猜的范围写进文档。

## 5. 审计结论

- **可以对外说**：v2.2 实现了五层语义、会话语义、接口级 ACL 解析、入向 ACL 采集、
  链路事实、区域/角色关键性映射，并有对应单测；
- **不能对外说**：参数已可在生产通过 config.ini 调整（A-1）；
  VLAN 闸门在容器环境生效（A-3）；v2.2 的 ROC 已重新验证（A-6）。


## 6. A-1 修复记录（v2.2.2，2026-10-27）

**诊断证据**（诊断日志，v2.2.1 部署）：

```
msg="SRD config source" cfg_nil=false cfg_type=*srdwrapper.srdConfigAdapter
get_supported=false srd.layered_graph="" effective_layered_graph=true
```

⇒ `kc.GetConfigObj()` 返回的是适配器，`loadConfig` 的类型断言全部落空。

**修复**：`unwrapConfig()` 沿 `GetConfigObj()` 链解包（最多 4 层），再交给 loadConfig。

**修复后现场验证**（kernel.ini 写入 false / 0.42 / 7 / 0.65 / max）：

```
msg="SRD config source" cfg_type=*config.Config get_supported=true srd.layered_graph=false
msg="SRD effective config" layered_graph=false transmission=0.42 max_path_depth=7
    path_decay=0.65 prop_cap=0.25 aggregation=max horizon_days=7
```

→ **A-1 关闭**；v2.2.1 中"不能声称参数可调"的限制正式解除。
剩余 A-3…A-9 仍按 §4 计划推进。


## 7. A-6 复验结果（v2.2.3，2026-10-27）

用 v2.2.3 的 `srdroc` 对 **同一批 10 轮实测真值**重新评估：

| 轮 | 负样本 | layered AUC |
|---|---|---|
| 1 | 16 | 0.990 |
| 2 | 14 | 0.908 |
| 3 | 12 | 0.964 |
| 4 | 10 | 0.829 |
| 5 | 11 | 0.831 |
| 6 | 9 | 0.905 |
| 7 | 10 | 0.804 |
| 8 | 13 | 0.849 |
| 9 | 13 | 0.868 |
| 10 | 10 | 0.936 |

汇总：**mean 0.888，sd 0.062，95% CI ±0.039**（与 v2.0 完全一致）。

**解读（诚实）**：该数据集只包含**转发策略**事实（接口级 ACL），没有
L1 链路 down、没有 VLAN、没有入向 ACL，因此 v2.2 新增语义**不改变判定**。
也就是说：**v2.2 的增益没有被这批数据测到**，需要含 L1/L2/入向事实的新数据集。
这不是回归，是"证据覆盖不到新能力"。

### A-4 现场实验（补充证据）

在 `domB-web` 上临时加 `input` 规则（`ip saddr 172.22.10.0/24 drop`），实测：

| 对 | 实测 | 说明 |
|---|---|---|
| A→B | 不通 | 请求被 B 的 INPUT 丢弃 |
| B→A | 不通 | 回程包同样被 B 的 INPUT 丢弃（有状态语义） |
| C→B | 通 | 对照（但受当时路由器 ACL 状态影响，仅作参考） |

模型（带 inbound 事实）对 A→B 判 blocked，但**无法表达"B→A 的连接因回程被丢而失败"**
——它只校验目标侧入向规则。这与 A-4 的判断一致：**单向入向规则已建模，
有状态回程未建模**。现场实验因路由器 ACL 处于上一轮 ROC 的残留状态，
不作定量结论，仅作为方向性证据。

### 结论

- A-6 **关闭**：复验完成，且明确记录"增益未被测到 / 需要新数据集"；
- A-4 保持 **"已用例化 + 有状态回程未建模"**；
- 下一步若要量化 v2.2 增益，需要构造含 VLAN/L1/入向 ACL 的随机数据集
  （当前 8 台主机的容器环境 VLAN 不可见，成本较高）。

### A-7b（已由 A-7c 关闭）

A-7 代码修复（`isPublicAddress`）已合并、单测通过、agent 二进制已确认更新
（hash 一致、10:19 启动），但 **`topology list` 里 `domC-router` 仍显示 `dmz`**。
按代码推断应为 `internal`（全部 IPv4 私网）。

结论：**运行时 zone 未刷新**，问题在"注册表更新/展示"这一侧，而不是 zone 推断函数。
待查方向：`TopoNode.Zone` 是否被心跳 `RecordNetworkFacts` 覆盖（可能是持久化旧值优先、
或 heartbeat 的 NetworkInfo 只在特定条件下更新）。A-7 代码修复保留，A-7b 记为开放项。


## 8. A-7b / A-7c 结案（v2.2.4）

新增 `topology facts recorded` 日志后拿到实证：

```
host_id=domC-router zone=dmz    subnets=5
host_id=domC-mon    zone=public subnets=1
```

⇒ 注册表更新链路正常，**问题在 zone 推断函数的输入判定**：
domC 使用 `100.64.0.0/24`（CGNAT），`IsPrivate()` 不覆盖它，`IsGlobalUnicast()` 为真
⇒ 被判公网 ⇒ `dmz`/`public`。

修复后现场验证（v2.2.4 分发 7 台 agent）：

```
domC-router   internal
domC-mon      internal
domA-web      internal
```

**A-7b 关闭**（结论：非注册表问题）；**A-9 关闭**（新增 Init 级集成测试
`TestManagerInitAppliesConfig`，覆盖 KernelContext → Init → loadConfig → cfg/pipeline）。

## 9. A-6 数据集复验（v2.2.4，2026-10-27）

8 轮混合场景（转发 ACL / 主机入向 ACL / 链路 down），每轮全量实测真值，
并向模型提供 policies/inbound/links 事实：

| 指标 | flat | layered |
|---|---|---|
| AUC 均值 | 0.462 | **0.884** |
| 链路 down 轮 | ~0.45 | **0.955–0.979** |
| 入向 ACL 轮 | ~0.42 | **0.681–0.775** |

结论：L1 语义有效；入向语义部分有效，低分轮与 A-4（有状态回程不建模）一致。
**A-6 关闭。** 报告：`docs/2-experiments/srd-bench/v22-facts-dataset-20261027.md`。

## 10. A-4 关闭（v2.2.5）

修复内容：同子网 `Adjacent` 与路径端点 `finalizePath` 都按**会话语义**校验入向策略
（目标拒绝来源 ⇒ blocked；源端拒绝目标网段 ⇒ 回程被丢，同样 blocked）。

同一批真值复算：R2 0.775 → **0.977**，R3 0.681 → **1.000**；
全体 mean 0.884 → **0.959**，95% CI ±0.074 → **±0.034**。
**A-4 关闭。**
