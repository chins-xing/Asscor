# Asscor v0.2.2 代码审计问题清单
## 一、中危问题
### 1. 扩展检查命令绕过全局命令白名单机制
文件路径：`internal/extmgr/extension_manager.go`
函数：`buildExtCheckFunc()`
问题详情：扩展配置`checks.json`中定义的command命令字符串，直接通过`sh -c`创建进程执行，未经过`common/exec.go`实现的全局命令白名单校验、shell特殊字符过滤逻辑。若加载来源不可信的恶意扩展，可直接执行任意操作系统shell命令，违背程序设计的执行策略白名单安全约束。

### 2. 算法完整性校验逻辑永久失效
文件路径：`internal/integrity/algo.go`
函数：`VerifyAlgo()`
问题详情：常量`expectedAlgoDigest`为空字符串，在校验流程中判断该常量为空时直接返回true。无论SSAM、Prism相关算法源码、常量是否被篡改，完整性校验均判定合法，算法防篡改保护机制无法生效。

### 3. Agent远程命令签名缺少防重放机制
文件路径：`internal/agent/agent.go`
函数：`verifyCommandSignature()`
问题详情：HMAC签名数据源仅包含CommandId、命令名称、请求参数，未引入时间戳、一次性随机数nonce。攻击者若捕获合法已执行命令的签名数据包，可重复发送数据包执行相同指令，存在重放攻击风险。

### 4. 检查项执行超时引发Goroutine与资源泄漏
文件路径：`internal/agent/agent.go`
函数：`runChecks()`
问题详情：检查任务设置60秒执行超时，触发超时时仅向上返回超时结果，执行`c.Run()`的内部goroutine无上下文取消机制。若检查项发生阻塞、长时间挂起，goroutine持续常驻运行，持续累积会造成goroutine数量暴涨、文件描述符耗尽、内存泄漏。

### 5. Linux平台反调试检测手段单一，易于绕过
文件路径：`internal/integrity/debug_linux.go`
函数：`IsDebugged()`
问题详情：仅依靠读取`/proc/self/status`内TracerPid数值判断程序是否被调试。该检测方式基础，可通过LD_PRELOAD劫持文件读取、ptrace技巧、修改/proc伪文件返回内容等多种手段绕过，无法有效抵御动态逆向调试。

## 二、低危问题
### 1. HMAC签名密钥采用相对路径，依赖进程工作目录
文件路径：`internal/integrity/sign.go`
函数：`loadOrCreateKey()`
问题详情：密钥文件路径硬编码为相对路径`certs/ASSCOR-assessment-key`。程序从不同工作目录启动时，会读取、生成不同目录下的密钥文件，造成密钥不一致；若工作目录被恶意篡改，存在加载非可信密钥风险。

### 2. 远程命令执行输出完整记录日志，存在敏感信息泄露风险
文件路径：`internal/agent/agent.go`
函数：`runCommand()`
问题详情：远程指令执行后的全部标准输出直接写入运行日志。若命令输出包含账号、密钥、证书等敏感内容，日志文件将持久存储敏感数据，引发信息泄露。

### 3. 配置文件解析未限制最大读取大小
文件路径：`internal/config/config.go`
函数：`Parse()`
问题详情：解析配置文件时不存在文件体积上限校验。加载超大尺寸恶意构造配置文件时，会一次性读取全部内容至内存，存在内存耗尽拒绝服务隐患。

### 4. 检查项注册表查询性能低效
文件路径：`internal/checks/registry.go`
函数：`GetByID()`
问题详情：检查项存储底层使用切片结构，根据ID查询时采用线性遍历方式，时间复杂度O(n)。随着内置检查项、自定义扩展检查项持续增加，查询耗时逐步上升。

### 5. 文件读取缓存无最大容量限制
文件路径：`internal/checks/linux/checks.go`
结构体：`fileReadCache`
问题详情：文件缓存仅设置数据过期时间，未限制缓存最大条目数量。持续扫描大量系统文件场景下，缓存无上限增长，持续占用堆内存。

### 6. 模块初始化依赖init执行时序，缺少显式管控
问题详情：多处模块在`init()`函数执行注册逻辑，模块间存在隐式依赖。Go语言init执行顺序规则复杂，版本迭代后容易出现初始化时序错乱，引发空指针、注册失效等隐性故障。

### 7. 对外错误信息泄露内部程序细节
问题详情：多处函数直接返回原始底层错误，错误信息包含本地绝对文件路径、内部函数名称。攻击者可依靠错误信息掌握服务器目录结构、程序内部实现细节，辅助进一步渗透。

## 三、代码质量问题
### 1. assessor.go文件职责过度臃肿
文件路径：`internal/engine/assessor.go`
问题详情：单文件代码量超过1100行，同时承担评估流程编排、SPC指标计算、ATT&CK框架映射、边缘因子运算多项独立职责，不符合单一职责原则，后续迭代、单元测试难度较高。

### 2. model包形成中心化依赖
问题详情：全部业务数据模型统一放置model包，项目几乎所有模块直接依赖model包。任何数据结构修改会触发大量模块联动变更，代码耦合程度高。

### 3. 配置解析逻辑存在大量重复样板代码
文件路径：`internal/config/config.go`
问题详情：各个配置分区解析逻辑重复编写if-else分支，未封装通用反射解析工具，代码冗余，新增配置项时维护成本高。

### 4. 存在两套独立组件注册体系
问题详情：系统同时存在checks包独立注册器、内核DI容器两套注册机制，两套机制互不打通，增加开发维护负担，容易出现组件注册遗漏、状态不一致问题。
