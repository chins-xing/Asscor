**日期**: 2026-08-13 | **版本**: v0.2.3 | **性质**: 定位延迟问题后的替代方向

---

## 一、核心结论

**可行，且是"流式改造"的正确替代方向。**

用户判断正确：流式检测改造会引入并发失控（海量流式事件 + goroutine 无界增长），威胁内核稳定性。而**基于 ATT&CK/SRD 的批处理攻击链推演**——计算全局行动策略——不引入流式并发，完全在现有"评估后触发"的批处理框架内完成。

## 四、"全局行动策略"计算层设计

### 4.1 计算流水线

```
推演攻击路径（现有能力）          → 全局行动策略（新计算层）
─────────────────────            ─────────────────────
1. PredictRisk(检测技术)    →     4. 阻断点计算（关键节点识别）
2. findPaths(BFS 推演)      →     5. 策略排序（风险×成本×收益）
3. FindPropagationPaths     →     6. 行动建议输出
   (主机传播路径)
```

### 4.2 新增能力（非并发密集，批处理）

| 新能力 | 输入 | 输出 | 复杂度 |
|------|------|------|:---:|
| **阻断点计算** | 推演路径集合 | 关键阻断节点（cut vertex） | O(V+E) |
| **策略排序** | 阻断点 + 风险 | 排序后的行动列表 | O(n log n) |
| **行动建议** | 排序策略 | 全局行动策略 | 纯计算 |

### 4.3 不引入并发失控的原因

| 特性 | 流式改造 | 推演+策略 |
|------|:---:|:---:|
| 触发时机 | 实时流事件 | 评估后批处理 |
| 并发模型 | 无界 goroutine | 串行计算 |
| 数据规模 | 海量流式 | 有限路径集合 |
| 内核影响 | 🔴 失控风险 | 🟢 可控 |

## 六、与"定位→行动"闭环的关系

本方案将"定位"升级为"定位→推演→行动"：

```
定位(Locate) ──→ 推演(Predict) ──→ 全局行动策略(Strategy)
     │                │                    │
  攻击者当前位置    可能的后续路径        防御方最优阻断点
     │                │                    │
  ATT&CK归因       transMatrix BFS       阻断点计算+排序
  SRD传播路径      paths DFS              → Blocker 接口
```

**关键洞察**：这正好衔接之前实现的 `LifecycleEngine` 状态机——`Locator`（定位）+ `Blocker`（阻断）接口已定义，本方案填补中间的"推演→策略"计算层，形成完整闭环。

## 七、裁定

**可行，推荐作为"定位延迟问题"的替代方向。**

| 结论 | 说明 |
|------|------|
| 替代流式改造 | ✅ 批处理推演，无并发失控 |
| 白盒确定性 | ✅ 硬编码矩阵，可审计 |
| 推演基础 | ✅ 已具备（transMatrix + paths） |
| 需新增 | 阻断点计算 + 策略排序（纯计算，非并发密集） |
| 与 LifecycleEngine 衔接 | ✅ 填补 Locator→Blocker 的中间层 |

### 推荐落地顺序

1. 🟢 补全 transMatrix（15 → 60+ 技术，覆盖主流攻击链）
2. 🟢 实现阻断点计算（基于推演路径的关键节点识别）
3. 🟡 实现策略排序（风险×成本×收益）
4. 🟡 衔接 LifecycleEngine（策略 → Blocker 接口）

**核心结论**：放弃流式改造是正确决策（避免并发失控），基于 ATT&CK/SRD 的批处理攻击链推演 + 全局行动策略计算，是兼顾"精度"与"内核稳定性"的可行替代方向，且全程白盒确定性。
