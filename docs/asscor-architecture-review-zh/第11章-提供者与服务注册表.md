# 第 11 章 — 提供者与服务注册表

现代运行时系统由许多独立组件组成，必须在不紧密耦合的前提下协作。Asscor 引入了提供者导向的架构，由集中式服务注册表支撑。

提供者代表一种能力而非实现，消费者应仅依赖提供者接口，遵循依赖倒置原则。每个运行时管理的服务遵循相同的注册流程：创建 → 注册 → 发现 → 使用 → 释放。

消费者通过注册表定位服务，这种架构显著减少了编译时耦合。注册表自然支持依赖注入——组件在初始化期间接收所需服务，而非手动构建依赖。

提供者接口允许多实现共存——日志器（控制台/文件/远程）、报告提供者（JSON/HTML/Markdown/REST API）。消费者保持对实现细节的无知。新能力可通过注册额外的提供者引入而无需修改内核。

注册表不应成为包含无关功能的全局对象——不应存储运行时状态、实现业务规则、充当每个对象的服务定位器。注册表存在是为了管理服务，而非应用逻辑。
