# 第 16 章 — 架构审查

软件架构不应仅通过当前实现来评估，还应通过其随时间演进的能力来评估。Asscor 逐渐揭示自己不仅仅是评估应用——它代表了构建运行时导向的评估平台的尝试。

并非每个组件都以相同速度演进。稳定层（运行时内核、证据模型规范、评估接口契约）应极少变化。中度稳定层（特定评估引擎、插件实现）可能随着实践发展而演进。频繁变化层（安全规则、威胁情报、组织策略）持续更新。

核心原则贯穿整个代码库——依赖反转、控制反转、单一职责。评估引擎是可替换的——当前 SSAM 是实现的一种可能。未来实现可替代 SSAM 而无需修改运行时、插件接口或证据模型。这种可替换性是架构最重要的长期保障之一。

架构的主要威胁不是技术选择，而是架构原则的逐渐侵蚀——内核逐渐积累业务逻辑、插件开始直接通信、评估语义泄漏到运行时代码中。
