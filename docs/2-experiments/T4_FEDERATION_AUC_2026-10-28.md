# T4 联邦 AUC 对照：单节点视角 vs 主端合并（2026-10-28）

> 问题：**联邦架构下的 AUC 到底变多少？**
> 做法：同一批实测真值，分别用"单节点视角"（V1）与"主端合并图"（V2）评分。

## 1. 实验设计

- **网络**：30 个 T4 agent（3 组×10，分布在 4 个 vnet），节点 kernel nk1/nk2/nk3，
  主 kernel 合并图含 40 主机（30 新 agent + 旧实验域 10）。
- **场景**：`asc-agt-nk1-02`（941）的 INPUT 拒绝 `asc-agt-nk1-01`（940）的 /32。
- **真值**：30 源 × 29 目标 = **870 对**，逐台实测 ping（负样本 2：940↔941 双向）。
- **V1（单节点视角）**：每对按**源主机所属节点**的图评分；该节点看不到的目标（跨节点）按 0 分。
- **V2（主端合并）**：`/federation/export` 导出的合并图（40 主机 + 策略事实）统一评分。
- 评分：`fevauc`（与 `topology.HostReachable` 同一 API；score = 1−exp(−Σ decay^(hops−1)×probable权重)，
  decay=0.80、depth=5、rss 聚合）。

## 2. 结果

| 模型 | AUC | 说明 |
|---|---|---|
| **V2 主端合并（40 主机）** | **0.992** | 能看到全部主机 + 节点上报告的策略事实 |
| **V1 单节点视角（每节点 10 主机）** | **0.873** | 跨节点目标不可见 ⇒ 按 0 分（漏报） |
| **差值** | **+0.119** | 这就是"联邦合并"在这批真值上的增益 |

分节点全真值（各节点图独立评分）：

| 节点图 | AUC | 原因 |
|---|---|---|
| nk1 | 0.959 | 负样本对（940/941）都在 nk1 内，能判出 |
| nk2 | 0.467 | 图里没有路由器 ⇒ 跨 vnet 全判 blocked（漏报） |
| nk3 | 0.467 | 同上 |

## 3. 解读

1. **联邦的价值是"可见性"**：单节点只能覆盖自己 10 台，跨节点对直接变成不可见（0 分），
   AUC 从 0.992 掉到 0.873；节点图缺少共享路由器时更差（0.467）。
2. **主端合并必须带图事实**：v0.1 只有摘要时，主端连"跨节点是否可达"都答不了；
   v0.2 的 `host_facts/policy_facts` 才让 V2 成立。
3. **本场景负样本太少（2 个）**：AUC 绝对值敏感，下一轮应加"多组 ACL + 多跳"把负样本
   提到 50–100，并让 decay/depth 真正影响排序。

## 4. 复现

- 真值：`t4-auc-truth-20261028.csv`（870 行）
- 逐对分数：`t4-auc-v2-dump-20261028.csv`、`t4-auc-v1-nk{1,2,3}-dump-20261028.csv`
- 工具：`cmd/fevauc`（ARC 专属；读 topology JSON + truth CSV + srcmap + hostmap，输出逐对分数与 AUC）
- 合并图导出：主 kernel `GET /federation/export`（token 保护）

## 5. 结论

在本实验环境下，**联邦合并把 AUC 从 0.873 提到 0.992（+0.119）**；
单节点视角的损失主要来自"跨节点主机不可见"和"共享路由器不在本地图"。
这条结论支撑 v0.2 的设计：联邦层必须传**图事实**，而不只是聚合摘要。
