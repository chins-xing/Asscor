# SRD v2.3 T3：`srd check` 可达性查询（2026-10-28）

> 目标：让运维/演示可以直接问"为什么 A 到 B 判不通"，输出 verdict、路径、阻断点、原因、未知项。

## 1. 用法

```bash
asscor-cli            # 进入 CLI
srd check domA-web domB-web
srd check domA-web domB-web --json
```

实现：`srd.Manager.CheckReachability`（`internal/engine/srd/check.go`）→
CLI 内置命令 `srd`（`internal/cli/srd_commands.go`）→ kernel `Bootstrap` 后注入 reach checker。

## 2. 现场输出（VM 910，v2.3.5）

```
  srd check  domA-web -> domB-web
  verdict : reachable   (paths=1)
  path    : domA-web -> domC-router -> domB-web
    - domC-router    172.22.10.0/24     reachable  policy allow (default)
    - domB-web       172.23.10.0/24     reachable
  layers  : hosts=10 subnets=5 vlans=0 policies=1 forwarding=2
```

JSON 模式输出完整结构（`best.nodes` / `best.steps` / `stats`）。

## 3. 实现要点与两个真实缺陷

1. **CLI 错误不可见**：socket 会话只渲染 `Output`、不渲染 `Err`，而 handler 最初只写 `Err`
   ⇒ 命令"静默无输出"。修复：错误同时写入 `Output`。
2. **位置参数未落 Params**：`srd check A B` 的 `src/dst` 为空 ⇒ 回退 `ctx.Args`。
3. **图滞后**：`srdwrapper` 注入的快照在启动早期只有 1 个 host ⇒ 误报 `source_unknown`。
   修复：`CheckReachability` 优先 `BuildLayeredFromRegistry()` 现场重建，注入图仅兜底。

## 4. 验证边界（诚实记录）

- **reachable 路径**：现场实测通过（路径/步骤/统计完整，JSON 正常）。
- **blocked 现场演示**：最后一次尝试里路由器规则被**追加在无条件 accept 之后**
  （真实流量也未被拦），因此 `reachable` 与实测一致，不能作为 blocked 演示；
  blocked 语义已由单测（`TestCheckReachabilityBlocked`）与 v2.2/v2.3 数据集覆盖。
- 策略事实刷新依赖 agent 心跳周期（实测约 30–90s），演示时需等待或重启 agent。

## 5. 结论

T3 完成：查询接口可用、可解释、可 JSON 化。剩余 T4（跨环境 ROC）。
