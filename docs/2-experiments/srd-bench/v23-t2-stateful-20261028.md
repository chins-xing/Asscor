# SRD v2.3 T2：状态化建模实测（2026-10-28）

> 目标：验证"有状态防火墙（`ct state established,related accept`）"下出现的
> **单向可达**能否被正确判定，并与实测对照。

## 1. 场景

在 `domA-db`（172.22.10.12，域 A）的 INPUT 链按真实运维顺序配置：

```
ct state established,related accept
ip saddr 172.22.10.11/32 drop
```

语义：
- `domA-web → domA-db`：新连接请求命中 drop ⇒ **不通**；
- `domA-db → domA-web`：B 自己发起，回程 A→B 命中 conntrack（ESTABLISHED）⇒ **通**。

## 2. 结果

| 方向 | 实测 | 模型（v2.3.1） | 判定 |
|---|---|---|---|
| domA-web → domA-db | 不通 | `blocked`（`inbound policy denies … → domA-db`） | ✅ 一致 |
| domA-db → domA-web | **通** | `reachable` | ✅ 一致 |
| 跨域对照（A↔B） | 通 | `reachable` | ✅ |

- 数据：79 条实测 ping，折叠后 1 个负样本 / 77 个正样本；
- **layered AUC = 1.000**（flat 0.427）；
- 对照（无状态，v2.2.5 数据集）：同一规则没有 `ct accept` 时双向都不通，
  模型也判双向 `blocked`。

## 3. 实现要点（v2.3.1）

- 事实：`NetworkInfo/TopoNode/HostFacts` 增加 `StatefulInput`；agent 检测
  `ct state established,related accept`（nft 与 iptables 两种写法）；
- 模型：邻接与端点改为**方向性会话判定**：
  1. 源端 OUTPUT 允许；
  2. 目标 INPUT 允许**新连接**；
  3. 回程到达源端 INPUT：**源端有状态 ⇒ 放行**，否则按静态规则；
- 这使 `A→B` 与 `B→A` 可以不同，正确表达"单向可达"。

## 4. 排障记录

- 第一版复核用了旧 `checkpath`（未读 `stateful_input`）→ 显示 922→921 blocked，
  与 srdroc 的 AUC 1.000 矛盾；换 2.3.1 版工具后一致。
- 结论：**验证工具必须与模型版本同步**，否则"证据"会骗人。

## 5. 结论

T2 完成：状态化语义在真实环境可判定，且能区分"无状态双向断"与"有状态单向可达"。
剩余 T3（`srd check` CLI）、T4（跨环境 ROC）。
