# SRD 路径识别能力实验设计（三域集群）2026-10-27

> 目标（用户 2026-10-27 定）：验证 **SRD 在复杂网络中的路径识别能力与误判率**。
> SSAM 分数不是主角，它只是 SRD 的输入；拓扑负责制造"多跳 / 可见性差异"。
>
> 四步：
> 1. 通过对部分 CT 的针对性修复，造出**真实的 SSAM 分数差异**（喂给 SRD 的差异化输入）；
> 2. 模拟**多条攻击链**：长度不同（1/2/3 跳）、可见性不同（有/无 agent）；
> 3. 用已知 ground truth 算 SRD 的 **precision / recall / 误判率**；
> 4. 扫 SRD 参数（运营可调），看能否提升精度、降低误判。

## 1. 先解决"能不能测"（2026-10-27 已完成）

盘点结论（代码事实）：

| 能力 | 现状 | 影响 |
|---|---|---|
| 多跳路径枚举 | `prism.FindPropagationPaths` 已实现（DFS + PathDecay + MaxPathDepth），但 **SRD/kernel 从不调用** | 生产上只有分数，**没有路径输出** |
| 边构造 | 只有"同子网一跳"（`areConnected`），跨子网无边 | 跨域路径**零召回** |
| 参数入口 | 仅 `[srd] sync_interval_sec`；`transmission`/`path_decay`/`prop_cap`/`max_depth` 无配置项 | 无法做可调性实验 |
| 可见性模型 | 只统计"注册了 agent 的主机"；路由器等基础设施若不装 agent 就不可见 | 决定跨域路径能否被识别 |

本次补上的：`internal/engine/srd/graph.go` 导出与线上**同一份**构边规则；
`cmd/srdbench` 离线基准（路径/可达 precision、recall、排序一致率、参数扫描）。

## 2. 基线结果（真实分数：6 台 46.78、domC-mon 40.42）

`cmd/srdbench -topology docs/2-experiments/srd-bench/three-domain-current.json`

| 场景 | c1 A内部 | c2 A→B | c3 A→C | c4 B→C |
|---|---|---|---|---|
| 路由器不可见（现状） | P=1.00 R=1.00 | **R=0.00** | **R=0.00** | **R=0.00** |
| 路由器可见 | P=0.50 R=1.00 | P=0.50 R=1.00 | P=0.50 R=1.00 | P=1.00 R=1.00 |

结论：
- **跨域 = 零召回**（SRD 看不到路由器就没边）；
- 路由器一可见，`A-web→router→B-web` 立刻被找到 ⇒ 能力受**可见性**支配；
- precision 0.50 来自"真实但更短的路径"（如 `A-web→router`），
  ⇒ ground truth 必须按**全部真实路径**建模，只写主链会把正确结果判成误报。

### 3.3 分数差异化（步骤 1 的落点）

对 `domA-web` 做**真实加固**（fail2ban/auditd/SSH 强化/关闭不必要服务），
`domB-web` 保持原样 ⇒ 两台同构主机的 SSAM 分数拉开；
再用 `srdbench` 把分数灌入，观察风险排序与路径优先级是否随分数变化。

### 3.4 参数扫描（步骤 4）

`srdbench -sweep transmission=0.05,0.1,0.2 -sweep max_depth=1,2,3,4 -sweep path_decay=0.6,0.8,0.95`
输出表格对比 precision / recall / 排序一致率；选出"运维可调且真能提升"的参数组合，
再决定是否把它接进 `config.ini [srd]`。

## 4. 验收口径

- **召回**：真实攻击链能被列出的比例（含不可见主机的链单独标注"不可见"）；
- **误报率**：SRD 列出的路径中，真实拓扑里**不存在**的比例（注意：真实但短路径不算误报）；
- **长度一致性**：SRD 给出的最短路径长度与真实最短跳数是否一致；
- **参数敏感性**：同一 ground truth 下，改变参数后上述指标的变化曲线。

## 5. 当前限制（如实记录）

- SRD 的边仍只有"同子网"一跳 ⇒ **多跳只能在"共享子网的主机链"上出现**
  （路由器/双宿主主机把子网串起来），没有真正的 IP 路由表/ACL 推理；
- 无 agent 的主机对 SRD **不可见**，这是设计上的盲区而非 bug；
- `srdbench` 目前不走 kernel 的完整 pipeline，而是复用其构边规则 + prism 路径枚举
  （保证规则一致；风险分数部分未含债务/时间项）。
