# SRD 路径识别能力实验设计（三域集群）2026-10-27

> 目标（用户 2026-10-27 定）：验证 **SRD 在复杂网络中的路径识别能力与误判率**。
> SSAM 分数不是主角，它只是 SRD 的输入；拓扑负责制造"多跳 / 可见性差异"。
>
> 四步：
> 1. 通过对部分 CT 的针对性修复，造出**真实的 SSAM 分数差异**（喂给 SRD 的差异化输入）；
> 2. 模拟**多条攻击链**：长度不同（1/2/3 跳）、可见性不同（有/无 agent）；
> 3. 用已知 ground truth 算 SRD 的 **precision / recall / 误判率**；
> 4. 扫 SRD 参数（运营可调），看能否提升精度、降低误判。

## 1. 先解决"能不能测"（2026-10-27 已完成）

盘点结论（代码事实）：

| 能力 | 现状 | 影响 |
|---|---|---|
| 多跳路径枚举 | `prism.FindPropagationPaths` 已实现（DFS + PathDecay + MaxPathDepth），但 **SRD/kernel 从不调用** | 生产上只有分数，**没有路径输出** |
| 边构造 | 只有"同子网一跳"（`areConnected`），跨子网无边 | 跨域路径**零召回** |
| 参数入口 | 仅 `[srd] sync_interval_sec`；`transmission`/`path_decay`/`prop_cap`/`max_depth` 无配置项 | 无法做可调性实验 |
| 可见性模型 | 只统计"注册了 agent 的主机"；路由器等基础设施若不装 agent 就不可见 | 决定跨域路径能否被识别 |

本次补上的：`internal/engine/srd/graph.go` 导出与线上**同一份**构边规则；
`cmd/srdbench` 离线基准（路径/可达 precision、recall、排序一致率、参数扫描）。

## 2. 基线结果（真实分数：6 台 46.78、domC-mon 40.42）

`cmd/srdbench -topology docs/2-experiments/srd-bench/three-domain-current.json`

| 场景 | c1 A内部 | c2 A→B | c3 A→C | c4 B→C |
|---|---|---|---|---|
| 路由器不可见（现状） | P=1.00 R=1.00 | **R=0.00** | **R=0.00** | **R=0.00** |
| 路由器可见 | P=0.50 R=1.00 | P=0.50 R=1.00 | P=0.50 R=1.00 | P=1.00 R=1.00 |

结论：
- **跨域 = 零召回**（SRD 看不到路由器就没边）；
- 路由器一可见，`A-web→router→B-web` 立刻被找到 ⇒ 能力受**可见性**支配；
- precision 0.50 来自"真实但更短的路径"（如 `A-web→router`），
  ⇒ ground truth 必须按**全部真实路径**建模，只写主链会把正确结果判成误报。

## 4. 验收口径

- **召回**：真实攻击链能被列出的比例（含不可见主机的链单独标注"不可见"）；
- **误报率**：SRD 列出的路径中，真实拓扑里**不存在**的比例（注意：真实但短路径不算误报）；
- **长度一致性**：SRD 给出的最短路径长度与真实最短跳数是否一致；
- **参数敏感性**：同一 ground truth 下，改变参数后上述指标的变化曲线。

## 5. 当前限制（如实记录）

- SRD 的边仍只有"同子网"一跳 ⇒ **多跳只能在"共享子网的主机链"上出现**
  （路由器/双宿主主机把子网串起来），没有真正的 IP 路由表/ACL 推理；
- 无 agent 的主机对 SRD **不可见**，这是设计上的盲区而非 bug；
- `srdbench` 目前不走 kernel 的完整 pipeline，而是复用其构边规则 + prism 路径枚举
  （保证规则一致；风险分数部分未含债务/时间项）。

## 6. 第一轮实测结果（2026-10-27，真实三域环境）

环境：CT 920 路由器（5 个接口，已装 agent）、917/922 域A、923 域B、924 域C、
925 `pivot-1`（双宿主：域B + 172.26.0.0/24）、927 `shadow-2`（172.26，可见）、
926 `shadow-1`（172.26，**故意不装 agent**）。新增 SDN `vnetD`（tag 300，172.26.0.0/24）。
策略：920 上 nftables 显式 `drop` 域A↔域B 转发，其余放行；A→C、A→D 可路由。

实测分数（kernel `assessment result`）：domA-web **47.34**（做过真实加固：sshd 强认证、
TMOUT、/etc/shadow 000、sudoers 0440），其余 CT 46.81，domC-mon 40.42，domC-router 42.67。

### 6.1 结果表（`srdbench`，默认参数）

| 攻击链 | 拓扑真值 | SRD 路径 P | SRD 路径 R | 说明 |
|---|---|---|---|---|
| c1 A-web→A-db（1 跳） | 通 | 0.50 | 1.00 | 找到了，但也列出了经路由器的短路径 |
| **c2 A-web→B-web（策略阻断）** | **不通**（nft drop） | **0.00** | **1.00** | **SRD 报告了一条策略禁止的路径 ⇒ 误报** |
| c3 A-web→C-mon（经路由器 2 跳） | 通 | 0.50 | 1.00 | 路由器可见后成立 |
| c4 A-web→shadow-2（3 跳，全可见） | 通 | 0.17 | 1.00 | 找到，但夹带多条短路径 |
| **c5 A-web→shadow-1（不可见主机）** | 通（真实） | 1.00 | **0.00** | **漏报：无 agent 的主机对 SRD 不存在** |

### 6.2 参数扫描（max_depth × path_decay）

- `max_depth=1`：2/3 跳链 **R 全部归零**（c3/c4/c5 R=0）——深度决定召回；
- `max_depth=2..3`：c3/c4 恢复 R=1，但 **c2 的误报在所有深度、所有 decay 下都存在**；
- `path_decay`（0.5/0.9）只影响路径累计风险排序，**不改变任何路径的存在性**。

### 6.3 结论：这是**理论缺陷**，不是调参问题

1. **边模型只有"同子网一跳"**（`areConnected` = 子网重叠），没有路由/ACL 推理。
   后果一：跨子网路径**只有在路由器本身也装了 agent** 时才能通过"共享子网"串起来；
   后果二：**策略阻断（nft/ACL）完全不被建模** ⇒ c2 在任何参数下都是误报。
2. **不存在的主机不能成为路径端点**：无 agent 的主机对 SRD 不可见，
   真实存在的攻击链 c5 **必然漏报**——这是设计盲区，不是参数能补的。
3. **参数只能调"搜索深度/衰减/聚合"，调不出"不存在的边"**
   ⇒ "运维自定义参数提升精度/降低误判"这个假设，在当前边模型下**只能部分成立**
   （深度影响召回；误报源于缺少 ACL/可见性模型，参数无效）。
4. 精度偏低还有一部分是**测量口径**问题：SRD 会列出"真实但更短"的路径
   （如 A-web→router），ground truth 应按"全部真实路径"建模，不能只写主链。

### 6.4 下一步（若要真正修复理论缺陷，而不是调参）

| 方向 | 内容 | 代价 |
|---|---|---|
| ① 引入路由器/网关为一等节点 | 拓扑里区分 host / router / shadow，按接口子网连边（而不是"共享子网即邻居"） | 中：拓扑模型 + 构边规则改造 |
| ② 建模 ACL/策略 | 采集 nft/iptables/ACL 结果，作为边的可用性约束 | 大：需要 agent 侧采集 + 语义 |
| ③ 显式未知/不可见节点 | 把"子网存在但主机未知"表示为不确定端点，输出"可能路径 + 置信度" | 中：输出模型改造 |
| ④ 校准测量口径 | ground truth 用完整路径集合 + 策略真值双轨 | 小：本基准已支持 |
